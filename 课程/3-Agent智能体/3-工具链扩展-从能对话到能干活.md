# 3.3 工具链扩展：从"能对话"到"能干活"

> 课程时长：120 分钟 | 含实操环节
>
> 目标：学完这节课，你能理解 MCP 协议和 Skill 生态的价值，掌握为 AI 添加自定义工具的方法，并扩展 AI 的能力边界。
>
> 前置要求：完成 3.1 和 3.2 课程。

## 一、为什么学这节？（10 分钟）

### 痛点场景

**场景一：AI 能聊天，但操作不了外部系统**
- 你想让 AI 帮你查数据库，它说"我没有这个功能"
- 你想让 AI 操作浏览器帮你填表，它说"我做不到"
- 你想让 AI 调用 API 获取实时数据，它说"我无法联网"
- **核心问题**：AI 的能力被限制在"对话"范围内

**场景二：每个工具都要重新配置，太麻烦**
- 装了一个 AI 工具，想让它连数据库，得写一堆代码
- 换了个 AI 平台，之前配置的工具全得重来
- **核心问题**：工具连接没有统一标准

**场景三：Skills 太多，管理麻烦**
- 装了 50 个 Skill，不知道哪个有用
- 想找一个特定功能的 Skill，翻半天找不到
- **核心问题**：缺乏统一的 Skill 管理和发现机制

### 核心矛盾

> **没有工具链的 AI，就像一个有大脑但没手脚的人——想得明白，干不了活。**
>
> MCP 协议 = 统一工具连接标准
> Skill 生态 = 可复用的能力模块
>
> 两者结合，让 AI 的手越来越长。

## 二、MCP 协议：AI 工具连接标准（25 分钟）

### 2.1 什么是 MCP？

**MCP（Model Context Protocol）**：模型上下文协议，是 Anthropic 提出的一个开放标准，用于统一 AI 模型与外部工具的连接方式。

**类比：**
- USB 标准：任何 USB 设备都能插到任何 USB 接口
- MCP 标准：任何 MCP 工具都能连接到任何支持 MCP 的 AI 模型

### 2.2 MCP 解决了什么问题？

**没有 MCP 之前：**
```
GPT → 需要写专门的插件代码
Claude → 需要写专门的函数调用
Hermes → 需要写专门的工具集成
```

**有了 MCP 之后：**
```
MCP 工具 → 任何支持 MCP 的 AI 模型都能用
```

### 2.3 MCP 架构

```
┌─────────────────────────────────────────────────────────┐
│                    MCP 架构                              │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ┌─────────────┐         ┌─────────────────────────┐    │
│  │  AI 模型     │◄───────►│  MCP Host（Agent 平台）  │    │
│  │  (Client)   │  MCP    │  (OpenClaw/Hermes等)     │    │
│  └─────────────┘  协议   └─────────────────────────┘    │
│                                          │               │
│                                          │ MCP           │
│                                          ▼               │
│                                ┌───────────────────┐     │
│                                │  MCP Server        │     │
│                                │  (工具提供者)       │     │
│                                │  - 文件系统        │     │
│                                │  - 数据库          │     │
│                                │  - 浏览器          │     │
│                                │  - API             │     │
│                                └───────────────────┘     │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 2.4 常用 MCP 工具

| 工具类型 | 代表 MCP Server | 功能 |
|----------|----------------|------|
| 文件系统 | `mcp-filesystem` | 读写文件、目录操作 |
| 数据库 | `mcp-sqlite`, `mcp-postgres` | 数据库查询、操作 |
| 浏览器 | `mcp-playwright` | 浏览器自动化、网页抓取 |
| API | `mcp-fetch` | HTTP 请求、API 调用 |
| 代码执行 | `mcp-python` | Python 代码执行 |
| Git | `mcp-git` | Git 操作 |

## 三、Skill 生态：AI 的能力插件（25 分钟）

### 3.1 什么是 Skill？

**Skill = AI 的技能插件**

一个 Skill 本质上是一个文件夹，核心是一个 `SKILL.md` 文件：
```
my-skill/
├── SKILL.md            ← 主文件（指令+规则+步骤）
├── references/         ← 参考文档
├── templates/          ← 模板文件
└── scripts/            ← 脚本资源
```

### 3.2 Skill vs MCP

| 维度 | MCP | Skill |
|------|-----|-------|
| 定位 | 工具连接标准 | 能力封装模块 |
| 内容 | 工具接口定义 | 指令+规则+步骤 |
| 类比 | USB 接口 | 驱动程序 |
| 关系 | Skill 可以通过 MCP 调用工具 | Skill 可以使用 MCP 工具 |

### 3.3 热门 Skill 推荐

| Skill 名称 | 功能 | 适合场景 |
|------------|------|----------|
| `web-research` | 网页搜索、信息收集 | 调研、竞品分析 |
| `ppt-generator` | PPT 自动生成 | 汇报、演示 |
| `code-review` | 代码审查 | 开发、质量把控 |
| `data-analyst` | 数据分析 | 报表、洞察 |
| `content-writer` | 内容写作 | 文案、文章 |
| `browser-automation` | 浏览器自动化 | 填表、抓取 |

## 四、实操环节：给 AI 扩展工具链（40 分钟）

### 实操 1：安装并使用一个 Skill（15 分钟）

**前提：** 已安装 `skb`（Skill Base CLI）

**步骤：**

1. **搜索 Skill**：
   ```bash
   skb search "web research"
   ```

2. **安装 Skill**：
   ```bash
   skb install web-research
   ```

3. **使用 Skill**：
   - 在 AI 对话中输入："使用 web-research Skill，搜索 AI 在教育行业的最新应用"
   - 观察 AI 如何调用搜索工具、整理结果

### 实操 2：为 AI 添加自定义工具（15 分钟）

**任务：** 创建一个"天气查询"工具

**步骤：**

1. **创建 Skill 目录**：
   ```bash
   mkdir -p ~/skills/weather-skill
   ```

2. **创建 SKILL.md**：
   ```bash
   cat > ~/skills/weather-skill/SKILL.md << 'EOF'
   # Weather Skill
   
   ## 功能
   查询指定城市的天气信息
   
   ## 使用方法
   当用户询问天气时，调用此 Skill
   
   ## 步骤
   1. 提取用户提到的城市
   2. 调用天气 API（https://wttr.in/{city}?format=j1）
   3. 解析 JSON 响应
   4. 格式化输出：温度、湿度、天气状况
   EOF
   ```

3. **安装自定义 Skill**：
   ```bash
   skb add ~/skills/weather-skill
   ```

4. **测试**：
   - 在 AI 对话中输入："北京今天天气怎么样？"

### 实操 3：体验 MCP 浏览器自动化（10 分钟）

**前提：** 已部署支持 MCP 的 Agent

**步骤：**

1. 在 Agent 中输入：
   ```
   请打开浏览器，访问 https://news.ycombinator.com
   抓取前 5 条新闻的标题和链接
   整理成 Markdown 列表格式返回给我
   ```

2. 观察 AI 的执行过程：
   - 调用浏览器工具
   - 打开网页
   - 抓取内容
   - 整理输出

## 五、工具链扩展的最佳实践（10 分钟）

### 5.1 设计原则

| 原则 | 描述 | 示例 |
|------|------|------|
| **最小权限** | 工具只授予必要的权限 | 读权限 ≠ 写权限 |
| **统一标准** | 优先使用 MCP 标准工具 | 便于跨平台复用 |
| **可观测性** | 记录工具调用日志 | 便于调试和审计 |
| **错误处理** | 工具失败时有降级方案 | 超时重试、备用工具 |

### 5.2 常见陷阱

| 陷阱 | 表现 | 解决方案 |
|------|------|----------|
| **工具过多** | 装了几十个 Skill，不知道用哪个 | 定期清理、分类管理 |
| **权限过大** | 工具可以删除文件、访问敏感数据 | 限制权限范围 |
| **依赖复杂** | Skill 依赖多个外部服务 | 简化依赖、提供离线方案 |
| **版本冲突** | 不同 Skill 依赖不同版本的库 | 使用虚拟环境隔离 |

## 六、常见问题 Q&A（10 分钟）

### Q1：MCP 和 Skill 哪个更重要？
**A：** 都重要。MCP 解决"怎么连"，Skill 解决"怎么用"。两者配合，AI 能力最大化。

### Q2：怎么判断一个 Skill 好不好？
**A：** 看 3 点：文档是否清晰、是否有实际案例、社区评价如何。

### Q3：自定义 Skill 难吗？
**A：** 简单 Skill 不难（写个 SKILL.md + 模板）。复杂 Skill 需要编程能力。

### Q4：工具链越多越好吗？
**A：** 不是。工具在精不在多。选 5-10 个最常用的，比装 50 个但不知道用哪个好得多。

### Q5：企业怎么管理 Skill 生态？
**A：** 
- 建立内部 Skill 仓库
- 制定 Skill 审核流程
- 定期评估 Skill 使用效果
- 及时更新和清理
