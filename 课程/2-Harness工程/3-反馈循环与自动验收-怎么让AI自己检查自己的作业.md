## 一、为什么学这节？（10 分钟）

### 痛点场景

**场景一：AI 生成内容后，还得人工审校**
- 让 AI 写了一篇报告，你得从头到尾检查一遍
- 让 AI 写了一段代码，你得跑一遍测试看看对不对
- 让 AI 做了一个 PPT，你得检查数据准不准
- **问题**：AI 干了 80% 的活，你还得干 20% 的审校——这 20% 往往最费时间

**场景二：AI 出错了，你得告诉它错在哪**
- AI 生成的代码有 Bug，你得找出问题告诉它
- AI 写的文案有事实错误，你得纠正它
- **问题**：审校-反馈-修改的循环，全靠人工驱动

**场景三：AI 不知道自己错了**
- AI 自信满满地给出一个错误答案
- 你问它"确定吗"，它说"确定"
- **问题**：AI 没有自我评估能力，或者评估不准确

### 核心矛盾

> **没有反馈循环的 AI，就像一个蒙眼开车的人——可能开很快，但不知道方向对不对。**
>
> 反馈循环的核心思想：**让 AI 生成内容 → 自动检查质量 → 如果不达标，自动修复 → 直到达标为止。**
>
> 自动验收的核心思想：**定义好验收标准，让 AI 自己判断是否通过，不通过就重来。**

## 二、反馈循环的原理（25 分钟）

### 2.1 什么是反馈循环？

**没有反馈循环：**
```
用户任务 → AI 生成 → 输出结果（可能好，可能差）
```

**有反馈循环：**
```
用户任务 → AI 生成 → 质量评估 → 是否达标？
                                ↓
                    ┌───────────┴───────────┐
                    ↓                       ↓
                达标 → 输出结果         不达标 → 错误分析 → AI 修复 → 重新评估
```

**核心组件：**
1. **生成器**：AI 生成内容
2. **评估器**：检查内容质量（可以是 AI 自评、规则检查、测试用例）
3. **修复器**：根据评估结果修复内容

### 2.2 反馈循环的 3 种模式

| 模式 | 评估方式 | 适用场景 | 示例 |
|------|----------|----------|------|
| **AI 自评** | 让 AI 自己评估自己的输出 | 文案、创意、翻译 | "请检查这段文案是否有事实错误" |
| **规则检查** | 用预定义规则检查 | 代码、格式、数据 | 代码 Lint 检查、JSON 格式验证 |
| **测试用例** | 运行测试用例验证 | 代码、计算、逻辑 | 单元测试、集成测试 |

### 2.3 真实案例：Hermes Agent 的自我修正

> 有用户让 Hermes Agent 自己写了一个数据质量检查 Skill，结果它真的开始自我修正了。

**工作流：**
```
1. AI 生成数据处理代码
2. 运行数据质量测试（测试用例）
3. 测试失败 → AI 分析错误原因
4. AI 修复代码
5. 重新运行测试
6. 测试通过 → 输出结果
```

**效果：**
- 人工干预从 100% 降到 20%（只需在 AI 多次修复失败时介入）
- 代码质量提升（每次修复都通过测试验证）
- 效率提升（AI 自动迭代，无需人工逐轮反馈）

## 三、自动验收的设计方法（25 分钟）

### 3.1 验收标准的定义

**好的验收标准 = 具体 + 可执行 + 可量化**

| 维度 | 差的验收标准 | 好的验收标准 |
|------|-------------|-------------|
| 代码 | "代码要写好" | "通过所有单元测试，无 Lint 错误" |
| 文案 | "文案要通顺" | "无错别字，句子长度 < 30 字，符合品牌 tone of voice" |
| 数据 | "数据要准确" | "与源数据对比，误差 < 0.1%" |
| PPT | "PPT 要好看" | "每页不超过 5 行文字，配色符合品牌指南，图表数据与源一致" |

### 3.2 自动验收的实现方式

**方式 1：测试用例（代码场景）**

```python
# test_code.py
def test_fibonacci():
    assert fibonacci(0) == 0
    assert fibonacci(1) == 1
    assert fibonacci(10) == 55
    assert fibonacci(20) == 6765

# AI 生成的代码必须通过这些测试
```

**方式 2：规则引擎（文案/数据场景）**

```python
# 文案验收规则
def check_article(article):
    errors = []
    if len(article) > 5000:
        errors.append("文章超过 5000 字")
    if "广告" in article:
        errors.append("包含敏感词'广告'")
    if article.count("，") < 10:
        errors.append("标点符号使用不足")
    return errors

# AI 生成的文案必须通过所有规则
```

**方式 3：AI 评估（创意/综合场景）**

```
# 评估 Prompt
你是一个资深编辑。请评估以下文章的质量：

评估维度：
1. 逻辑性：论点是否清晰，论证是否充分
2. 可读性：语言是否流畅，句式是否多样
3. 准确性：是否有事实错误
4. 吸引力：标题和开头是否吸引读者

请给出每个维度的评分（1-5 分），并指出需要修改的地方。

文章：
{article}
```

### 3.3 自动验收工作流示例：AI 写代码 + 自动测试

```
┌────────────────────────────────────────────────────────────┐
│              AI 代码生成 + 自动验收工作流                     │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  1. 用户输入需求："写一个 Python 函数，计算斐波那契数列"       │
│         ↓                                                  │
│  2. AI 生成代码                                             │
│         ↓                                                  │
│  3. 自动运行测试用例                                        │
│         ↓                                                  │
│  4. 测试结果                                               │
│     ↓                       ↓                              │
│   通过                     失败                             │
│     ↓                       ↓                              │
│  输出代码              分析错误原因                         │
│                            ↓                               │
│                       AI 修复代码                          │
│                            ↓                               │
│                       重新运行测试                         │
│                            ↓                               │
│                       最多重试 3 次                        │
│                            ↓                               │
│                   3 次仍失败 → 通知人工                    │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

## 四、实操环节：搭建带自动验收的 AI 工作流（40 分钟）

### 实操 1：用 AI 自评实现文案自动审校（15 分钟）

**步骤：**

1. **让 AI 生成文案**：
   ```
   请写一篇关于"AI 在教育行业应用"的短文，300 字以内。
   ```

2. **让 AI 自评**：
   ```
   请审校以下文章，检查以下问题：
   1. 是否有错别字或语法错误
   2. 是否有事实错误
   3. 语言是否流畅
   4. 是否有更好的表达方式

   文章：
   {AI 生成的文章}

   请直接输出修改后的完整版本。
   ```

3. **对比原文和修改后版本**：
   - 记录 AI 自评发现了哪些问题
   - 评估修改后的质量是否提升

### 实操 2：用测试用例实现代码自动验收（20 分钟）

**前提：** 有 Python 环境

**步骤：**

1. **创建测试文件** `test_fibonacci.py`：
   ```python
   import unittest

   class TestFibonacci(unittest.TestCase):
       def test_fibonacci_0(self):
           from fibonacci import fibonacci
           self.assertEqual(fibonacci(0), 0)

       def test_fibonacci_1(self):
           from fibonacci import fibonacci
           self.assertEqual(fibonacci(1), 1)

       def test_fibonacci_10(self):
           from fibonacci import fibonacci
           self.assertEqual(fibonacci(10), 55)

       def test_fibonacci_20(self):
           from fibonacci import fibonacci
           self.assertEqual(fibonacci(20), 6765)

   if __name__ == '__main__':
       unittest.main()
   ```

2. **让 AI 生成代码** `fibonacci.py`：
   ```
   请写一个 Python 函数 fibonacci(n)，返回第 n 个斐波那契数。
   要求：n >= 0，使用迭代实现（不用递归）。
   ```

3. **运行测试**：
   ```bash
   python test_fibonacci.py -v
   ```

4. **如果测试失败，让 AI 修复**：
   - 复制测试错误信息
   - 输入给 AI："以下测试失败了，请修复代码"
   - 重新运行测试

5. **循环直到测试通过**

### 实操 3：在 OpenClaw 中实现自动验收（5 分钟）

**前提：** 已部署 OpenClaw

**步骤：**

1. 在 OpenClaw 中输入：
   ```
   请写一个 Python 脚本，读取 CSV 文件并计算平均值。
   写完后，请自己运行测试验证是否正确。
   如果有错误，请自动修复，直到测试通过。
   ```

2. 观察 OpenClaw 的自动验收过程：
   - AI 生成代码
   - AI 运行测试
   - AI 分析错误
   - AI 修复代码
   - AI 重新测试

## 五、反馈循环的最佳实践（10 分钟）

### 5.1 设计原则

| 原则 | 描述 | 示例 |
|------|------|------|
| **明确标准** | 验收标准必须具体、可执行 | "通过所有单元测试"而不是"代码要好" |
| **限制循环次数** | 设置最大重试次数，避免无限循环 | 最多重试 3 次，失败后通知人工 |
| **记录日志** | 记录每次评估结果和修复过程 | 便于追溯和调试 |
| **分级验收** | 先快速检查基本项，再深度检查质量 | 格式检查 → 逻辑检查 → 质量检查 |

### 5.2 常见陷阱

| 陷阱 | 表现 | 解决方案 |
|------|------|----------|
| **自评偏差** | AI 自评过于自信，实际有问题 | 引入第三方评估（另一个模型或规则） |
| **标准过严** | 验收标准太高，AI 永远通不过 | 分级标准，先保证基本质量 |
| **标准过松** | 验收标准太低，差内容也能通过 | 定期review 和更新标准 |
| **无限循环** | AI 反复修复但始终通不过 | 设置最大重试次数 |

## 六、常见问题 Q&A（10 分钟）

### Q1：AI 自评可靠吗？会不会自己给自己打高分？
**A：** AI 自评有偏差是事实。解决方案：
- 引入第二个模型做交叉评估
- 用规则检查补充 AI 自评
- 对关键内容，仍需人工抽检

### Q2：自动验收能替代人工审校吗？
**A：** 不能完全替代，但能大幅减少人工工作量。建议：
- 自动验收处理 80% 的常规检查
- 人工抽检 20% 的关键内容
- 定期 review 自动验收标准

### Q3：反馈循环会不会很慢？
**A：** 会有一定延迟（每次循环增加模型推理时间）。优化方法：
- 用更快的模型做评估（小模型）
- 并行处理多个检查项
- 设置合理的重试次数上限

### Q4：怎么判断反馈循环是否有效？
**A：** 看 3 个指标：
- **通过率**：首次通过率 vs 最终通过率
- **循环次数**：平均需要几次循环才能通过
- **人工介入率**：多少次循环后需要人工介入

### Q5：非技术岗位怎么实现自动验收？
**A：** 不需要写代码也能实现：
- 用 AI 自评（让 AI 检查自己的输出）
- 用预定义 checklist（人工制定，AI 执行）
- 用 Dify 等低代码平台搭建验收流程

### 验收标准模板

```markdown
# [任务名称] 验收标准

## 基本信息
- 任务描述：
- 负责人：
- 验收人：

## 验收维度
| 维度 | 标准 | 检查方式 |
|------|------|----------|
| 完整性 | 是否包含所有必要内容 | 规则检查 |
| 准确性 | 是否有事实/数据错误 | AI 评估 + 人工抽检 |
| 格式 | 是否符合格式要求 | 规则检查 |
| 质量 | 是否达到预期质量 | AI 评估 |

## 通过条件
- 所有规则检查通过
- AI 评估得分 ≥ 4/5
- 人工抽检合格率 ≥ 95%

## 不通过处理
- 首次不通过：AI 自动修复
- 第二次不通过：AI 自动修复 + 通知负责人
- 第三次不通过：转人工处理
```
