# 先讲清楚：这不是“更会写代码”，是“更会交付” 🧱

> 来源: [马良的神笔x](https://mp.weixin.qq.com/s?__biz=MzU2NDAyNjY2NQ==&mid=2247484484&idx=1&sn=f4990e7a0399b57ac5bcedee6d3ac037&chksm=fd287e589a5aefee97473ff0cd709e4fe3a24a5ddc895e36ab336f9577fe1d7cda5696659c6f&mpshare=1&scene=1&srcid=04302v8uI8AdMneE9CIjWRD6&sharer_shareinfo=a57c8466e38930c43a4c89fa4d76a6d6&sharer_shareinfo_first=a57c8466e38930c43a4c89fa4d76a6d6) | 2026-04-30

## 摘要

你不是缺一个更聪明的模型。
你缺的是：让模型“按工程流程干活”的手脚。
mattpocock/skills 这套 Skill 的价值不在于提示词写得多漂亮，而在于它把工程师每天重复的三类工作，做成了可复用、可执行、可验收的流程：
- 需求怎么写清楚（PRD）
- 活怎么拆到能独立交付（Issues / tracer bullet）
- 怎么写到不烂尾（TDD 的竖切循环）
下面用工程视角，把它拆开讲透：你可以怎么用、它为什么好用、以及落地时最容易踩的坑。
很多人用 Agent 的体验是这样的：
- 代码能吐一堆
- PR 也能开
- 但最后你拿到的是一堆“看起来能用”的片段
真正工程交付要解决的是三件事：
1. 目标可对齐：到底要做什么
2. 过程可推进：怎么拆、怎么排依赖
3. 结果可验证：怎么测、怎么证明没回归
mattpocock/skills 的核心，就是把这三件事固化成可重复执行的 Skill。
这套仓库里 Skill 很多，但最能快速拉开差距的是这四件：grill-me → to-prd → to-issues → tdd。
