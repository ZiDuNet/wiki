# 检索知识库

搜索和综合 wiki 中的知识，回答用户问题。

## 搜索策略

### 1. 优先用 BM25 脚本（wiki_fts.py）

知识库超过 ~100 页后，直接用 SQLite FTS5 全文检索，效率远超扫 index.md：

```bash
cd <wiki-root>
python3 scripts/wiki_fts.py search "关键词" --limit 5
```

`<wiki-root>` 即知识库目录下的 `wiki/` 文件夹。

返回匹配的 wiki 页面路径和摘要片段，直接定位最相关的页面。

### 2. 补充扫 index.md

如果 BM25 结果不够全面，再读 `wiki/index.md` 扫描分类找到遗漏的相关页面。

### 3. 读取相关页面

读取找到的 wiki 页面。跟随 `[[wikilink]]` 拉取关联上下文。读够回答问题的页面即可，不要读整个 wiki。

### 4. 必要时查 raw 源文件

wiki 不够时，查 `wiki/sources/` 中的摘要页。只在 wiki 和摘要都不够时才去 raw 目录读原始文件。

## 综合回答

### 匹配回答格式

- **事实性问题** → 直接回答 + 引用
- **对比** → 表格或结构化对比
- **探索性问题** → 叙述 + 关联概念
- **清单类** → 列表 + 简要说明

### 引用来源

每个事实性声明都要用 `[[wikilink]]` 引用 wiki 页面：

> 根据 [[源文件 - 文章标题]]，核心发现是 X。这与 [[概念名称]] 中描述的更广泛模式相关。

### 重要的回答要存回 wiki

如果回答产生了有价值的内容——对比、分析、新发现、新关联——主动提议保存：

> "这个对比分析值得保留。要我存为综合页面吗？"

用户同意后：
1. 在 `wiki/synthesis/` 创建新页面（含 frontmatter）
2. 在 `wiki/index.md` 的 Synthesis 下添加条目
3. 追加到 `wiki/log.md`：`## [YYYY-MM-DD] query | 问题摘要`

**这是核心洞察：好的回答应该存回 wiki，让探索也产生知识复利。**
