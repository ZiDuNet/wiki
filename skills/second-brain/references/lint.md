# 健康检查

检查 wiki 的健康状况，发现问题并提供可操作的修复建议。

## 检查项

按顺序执行所有检查，最后汇总报告。

### 1. 失效的 wikilink

扫描所有 wiki 页面的 `[[wikilink]]`，验证目标页面是否存在。

```bash
grep -roh '\[\[[^]]*\]\]' wiki/ | sort -u
```

与 `wiki/` 中的实际文件交叉比对。

### 2. 孤立页面

找出没有入站链接的页面——没有其他页面通过 `[[wikilink]]` 引用它。

对 `wiki/sources/`、`wiki/entities/`、`wiki/concepts/`、`wiki/synthesis/` 中每个 `.md` 文件：
- 提取页面名称
- 在其他所有 wiki 页面中搜索 `[[页面名称]]`
- 没有任何页面链接它 → 孤立

### 3. 矛盾

读共享实体或概念的页面，找冲突声明：
- 两个源文件摘要对同一主题有对立观点
- 实体页信息与源文件摘要矛盾
- 日期、数据、事实性声明在不同页面不一致

### 4. 过时声明

交叉比对源文件日期和 wiki 内容：
- 概念页只引用旧来源，但同主题有更新来源
- 实体信息未更新，但有更新来源提到了该实体

### 5. 缺失页面

扫描 `[[wikilink]]` 指向但还不存在的页面。这些是 wiki 提到了但没给独立页面的主题。评估是否值得建页。

### 6. 缺失交叉引用

找讨论相同主题但没互相链接的页面：
- 实体页提到概念但没链接
- 概念页提到实体但没链接
- 源文件摘要覆盖同一主题但没互引

### 7. index 一致性

验证 `wiki/index.md` 完整准确：
- 每个页面都有 index 条目
- 没有指向已删除页面的条目
- 条目在正确的分类标题下

### 8. 数据缺口

基于当前覆盖范围建议：
- 频繁提及但缺乏深度的主题
- wiki 无法很好回答的问题
- 网络搜索可以补充的空白

## 报告格式

按严重程度分组：

**错误（必须修）**
- 失效 wikilink
- 页面间矛盾
- index 指向缺失页面

**警告（应该修）**
- 孤立页面
- 过时声明
- 频繁引用但缺独立页面的主题

**建议（可以优化）**
- 可以添加的交叉引用
- 可以补充的数据缺口
- index 条目可以更有描述性

每条包含：**问题** → **位置**（具体文件）→ **修复方式**

## 检查后

问用户：
> "发现 N 个错误、N 个警告、N 个建议。要我修复哪些？"

用户同意后修复，报告修改内容。

## 记录

追加到 `wiki/log.md`：

```
## [YYYY-MM-DD] lint | 健康检查
发现 N 个错误、N 个警告、N 个建议。已修复：[修复列表]。
```

## 检查时机

- **每摄入 10 个文件后** — 趁记忆新鲜发现引用缺失
- **至少每月一次** — 发现过时声明和孤立页面
- **重大查询前** — 确保依赖的 wiki 内容是健康的
