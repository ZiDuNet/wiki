# 摄入源文件

将 raw 源文件处理为结构化、相互链接的 wiki 页面。

## 确定待处理文件

1. 用户指定了文件 → 用指定的
2. 用户说"处理新文件" → 检测未处理文件：
   - 列出 raw 目录中所有文件（排除 `assets/`）
   - 读取 `wiki/log.md`，提取所有已摄入的文件名
   - raw 中不在日志里的 = 未处理
3. 没有未处理文件 → 告诉用户

## 处理流程（逐文件）

### 1. 完整读取源文件

读整个文件。如果有图片引用，记下——图片包含重要信息时单独查看。

### 2. 与用户确认要点

写出 3-5 个核心要点，问用户是否有特别想强调或跳过的。确认后再写。

### 3. 创建源文件摘要页

在 `wiki/sources/` 创建新文件，文件名用 slugified 标题：

```markdown
---
tags: [相关, 标签]
sources: [原始文件名.md]
created: YYYY-MM-DD
updated: YYYY-MM-DD
---

# 源文件标题

**来源：** 原始文件名.md
**摄入日期：** YYYY-MM-DD
**类型：** 文章 | 论文 | 记录 | 笔记

## 摘要

结构化摘要内容。

## 核心观点

- 观点1
- 观点2

## 提及实体

- [[实体名称]] — 简要说明

## 涉及概念

- [[概念名称]] — 简要说明
```

### 4. 更新实体和概念页

对源文件中提到的每个实体和概念：

**已有页面：**
- 读取现有页面
- 追加新信息，标注来源
- 更新 `sources:` 和 `updated:` 字段
- 发现矛盾时标注，同时引用两个来源

**没有页面：**
- 在对应子目录创建新页面：
  - `wiki/entities/` — 人物、组织、产品、工具
  - `wiki/concepts/` — 想法、框架、理论、模式
- 写聚焦摘要，基于当前源文件对该主题的描述

### 5. 添加 wikilink

确保所有相关页面互相链接。每次提到有独立页面的实体或概念都要 `[[链接]]`。

### 6. 更新 index.md

每个新页面在对应分类下添加一行：

```
- [[页面名称]] — 一句话摘要（不超过120字）
```

### 7. 更新 log.md

追加：

```
## [YYYY-MM-DD] ingest | 源文件标题
处理 原始文件名.md。新建 N 个页面，更新 M 个页面。
新实体：[[实体1]]、[[实体2]]。新概念：[[概念1]]。
```

### 8. 报告结果

告诉用户：
- 新建了哪些页面
- 更新了哪些页面（改了什么）
- 识别了哪些新实体和概念
- 是否发现矛盾

## 约定

- 源文件摘要页**只记录事实**，解读和综合放在概念页和综合页
- 单个源文件通常会涉及 **10-15 个 wiki 页面**，正常
- **优先更新现有页面**，只在主题足够独立时才创建新页面
