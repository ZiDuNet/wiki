| 01 | 🧠 先搞懂：Skills 是什么，不是什么  · 搜一搜：Hermes Agent Skills |

 

一句话：Skills 不是插件，是「可复用的工作流文档」。

 

插件是功能扩展，装了就一直跑。Skills 是知识文档——它告诉 Hermes「遇到这类任务，按这个流程走」。Hermes 按需加载，不装一百个技能就卡死。

 

|  |  |
| --- | --- |
| ❌ 错误理解  ▸ Skills = 装了就能用的插件  ▸ 装越多越好  ▸ 会占用很多内存 | ✅ 正确理解  ▸ Skills = 可复用工作流文档  ▸ 按需加载，装多不卡  ▸ 越用越精准，Hermes 自己优化 |

 

Skills 存在哪里？

|  |
| --- |
| ~/.hermes/skills/ ├── writing/          # 写作类 ├── data-science/     # 数据分析 ├── devops/           # 自动化 └── 你自建的skill/     # 个人定制 |

 

三大来源：

▸内置 Skills：安装时自动复制，70+个，覆盖15+类别，开箱即用

▸社区 Skills（Hub）：agentskills.io 下载，经65+项安全规则扫描，一键安装

▸自建 Skills：Hermes 从你的对话中自动提炼，或你手动写 SKILL.md

 

用法三种：

1.斜杠命令（最常用）：/plan 帮我规划Q2项目推进

2.自然对话：说需求，Hermes 自动匹配最合适的 Skill

3.查看清单：hermes skills list

 

|  |
| --- |
| 💡 Steve实战Tips  渐进式加载机制：Hermes 不会把所有 Skill 塞进对话，而是「看到任务才加载对应知识」，装100个也不慢，token 也不多花。 |

| 04 | 🔌 MCP 配置：让 Hermes 连上你的工作系统  · 搜一搜：MCP AI集成 |

 

MCP（Model Context Protocol）是让 AI 连接外部工具的标准协议。配置了 MCP，Hermes 就能直接读飞书日历、操作本地文件——而不只是聊天。

 

🔗 ① 飞书 MCP（央企最实用，优先配置）

 

配置后，你可以直接对 Hermes 说「帮我在飞书日历建一个明天下午3点的会」，它直接操作，不需要你打开飞书。

 

在 ~/.hermes/config.yaml 中添加：

|  |
| --- |
| mcp:   servers:     feishu:       type: url       url: https://mcp.feishu.cn/mcp       name: feishu-mcp |

 

配置后直接对话：

|  |
| --- |
| 帮我在飞书日历新建会议： - 时间：下周三下午3点 - 标题：Q2项目评审 - 参与人：张三、李四 |

 

📁 ② 本地文件系统 MCP（数据合规必配）

 

让 Hermes 只访问你指定的本地文件夹，读写工作文档不经过任何云端。央企数据合规要求高，这个必配。

|  |
| --- |
| mcp:   servers:     filesystem:       type: local       allowed\_paths:         - ~/documents/work         - ~/documents/reports         # 注意：不要把整个硬盘都开放 |

 

|  |
| --- |
| ⚠️ 踩坑预警  allowed\_paths 只放需要 Hermes 访问的文件夹，不要配置根目录或敏感目录。这是基本的数据安全意识，在央企更要注意。 |

 

🌐 ③ 搜索 MCP（让回答更准确、更及时）

 

给 Hermes 加上实时搜索能力，回答需要最新数据的问题时不再受模型知识截止日期限制。

|  |
| --- |
| mcp:   servers:     web-search:       type: url       url: https://mcp.tavily.com/mcp       name: search |

 

|  |
| --- |
| 💡 Steve实战Tips  Tavily 是境外服务。如果单位网络有限制，可替换为国内搜索接口，或直接用上一章安装的 web-search-enhanced Skill 代替，效果差不多。 |

| 05 | 🎯 初始调教：这3步决定 Hermes 好不好用  跳过这步，装再多技能也白费 |

 

这是最被忽视、也是最重要的一步。Skills 和 MCP 是工具，SOUL.md 和记忆训练才是让 Hermes「认识你」的过程。

 

|  |  |
| --- | --- |
| 第1步 | 写你的 SOUL.md（人设文件）  这是整个配置中最重要的一个文件，没有之一 |

 

SOUL.md 是 Hermes 的「认识你」档案，放在 ~/.hermes/SOUL.md。写得越详细，Hermes 越懂你的工作风格和领导偏好。

 

创建文件：

|  |
| --- |
| nano ~/.hermes/SOUL.md |

 

参考模板（按你实际情况修改）：

|  |
| --- |
| # 我的工作信息  ## 基本背景 - 单位：某央企集团 - 岗位：XX部门主任科员 - 日常工作：项目管理、汇报材料、跨部门协调  ## 写作风格偏好 - 公文格式：正式严谨，多用「根据」「结合」「为」等套语 - 汇报结构：结论前置，数据支撑，分点阐述 - 篇幅要求：领导喜欢简短，原则上不超过1页纸 - 禁忌：不要用太多形容词，领导嫌虚  ## 高频任务 - 每周：周报（每周五）、部门例会纪要 - 每月：月度汇报PPT提纲、项目进度报告 - 不定期：请示、项目申请、情况说明  ## 数据安全红线 - 不涉及财务数字，不对外分享内部文件 - 只操作 ~/documents/work 下的文件 |

 

|  |
| --- |
| 💡 Steve实战Tips  SOUL.md 不用一次写完，用了一段时间后你会知道还需要补充什么。每次 Hermes 生成的内容和你预期差距大，就说明 SOUL.md 还需要完善。 |

 

|  |  |
| --- | --- |
| 第2步 | 做3次教学对话，启动学习循环  这是 Hermes 「了解你」的过程 |

 

刚装好的 Hermes 没有你的历史记忆。用你最高频的3个工作场景各做一次完整对话，然后纠正它的输出：

 

▸教学对话①：写一份真实的周报，纠正格式和用词，说明领导喜欢的结构

▸教学对话②：起草一份常用请示，告诉它你们单位的抬头格式和落款要求

▸教学对话③：整理一次会议纪要，告诉它你领导偏好的纪要结构和详略程度

 

每次对话结束后，运行这个命令：

|  |
| --- |
| hermes memory consolidate |

 

这个命令让 Hermes 把这次对话的经验提炼成持久记忆，下次用的时候直接调用，不用再重复说明。

 

|  |  |
| --- | --- |
| 第3步 | 设置记忆自动备份  防止换电脑或重装后记忆丢失 |

 

Hermes 的 Skills 和记忆存在本地，不自动同步。设置每周定时备份到飞书文档：

|  |
| --- |
| hermes cron create "0 18 \* \* 5" \   "把本周新增的记忆摘要整理成文字，    发给我并备份到飞书文档「Hermes记忆备份」" |

 

|  |
| --- |
| ⚠️ 踩坑预警  Hermes 的 Skills 和记忆不跨设备同步。换电脑时，手动把 ~/.hermes/skills/ 和 ~/.hermes/memory/ 目录打包复制过去。 |
