多 Agent 不是"让 AI 更聪明"，是"把一个过载的 AI 拆开"。

我花时间看了 Hermes 的 Profile 系统，发现它解决的问题比我想的更根本——不是帮你换皮肤，是真的把记忆、Session、技能、行为配置全隔开。这篇就来拆这件事。

---

## 一、单 Agent 用久了会发生什么

你可能有过这种感受：刚开始用一个 AI 助手还挺好，但用了一段时间之后，它开始变得"模糊"。

问研究问题，它的风格开始带点写作腔；让它写代码，它又在解释一堆方法论。

原因不难理解：**记忆在污染，上下文在混淆，专业度在漂移。**

你不断往同一个 Agent 喂不同任务，它的"认知"会越来越像一锅粥——什么都有，什么都不精。

更好的思路不是让这个 Agent 更聪明，而是——把它拆开。

---

## 二、Hermes Profile 到底隔离了什么

上一篇我拆解过 Hermes 的整体架构和自学习循环（#01），这次聚焦它的 Profile 系统。

Profile 是 Hermes 里最被低估的功能。很多人以为它只是"改个名字"，其实它隔离的东西要深得多：

| 隔离维度 | 说明 |
| --- | --- |
| `config` | 每个 Profile 独立的模型配置、API 设置 |
| `memory` | 记忆库完全独立，互不干扰 |
| `sessions` | 对话历史各自存储，不共享 |
| `skills` | 每个 Profile 可以挂载不同技能集 |
| `personality` | 默认行为、语气、优先级各自定义 |
| `cron state` | 定时任务状态独立维护 |
| `gateway state` | 消息网关（Telegram 等）绑定状态独立 |

**关键点在于：多 Agent 系统失败，往往不是因为模型不够强，而是因为所有 Agent 共享了同一套状态。** 一个 Agent 的写作习惯"污染"了另一个的研究判断，这很常见。

## 三、四人小队：角色怎么拆

我搭了一套最小可用的多 Agent 团队，四个角色：

```
指挥官（Hermes 主 Profile）├── 小研：研究专员├── 小明：内容工程师└── 小图：系统调试员
```

**为什么用中文名？** 因为角色不只是标签，它是你对这个 Agent 期望的人格化锚点。叫"Alan"还是叫"小研"，在 SOUL.md 里写起来感受是不一样的。

### 指挥官（默认 Hermes Profile）

不亲自干每件事，负责拆解目标、分配任务、把各专员的产出合并成最终结果。

核心能力：规划、拆解、依赖管理、质量把关。

它想的是"谁做什么、按什么顺序"，不是"这件事怎么做"。

### 小研：研究专员

专门负责找证据、验证来源、整理信息。

它应该带点怀疑主义——不轻易相信单一信源，主动区分"已证实"和"听起来合理"。

**设计这个角色的核心价值是：保护其他 Agent 不被坏假设传染。** 如果小研输出的信息本身就错了，后面写稿的小明和改代码的小图都会跑偏。

### 小明：内容工程师

负责把研究结论变成人能读懂的东西。

它不需要记住完整的调研过程，只要接收干净的输入，专注于结构、节奏和读者视角。

这个角色存在的原因：**写作变差，通常是因为一个 Agent 同时在做研究员和写手。** 把这两件事拆开，各自质量都会上升。

### 小图：系统调试员

实现导向，直接、精确、以结果为准。

它的工作：写功能、排查 bug、审查代码、跑测试。

它不需要关心叙事风格是否优美，只关心：能不能跑、跑对了没有。

## 四、搭建步骤（完整命令版）

> **给非开发者的前置说明**：以下命令在终端（Terminal / 命令行）里运行。每行 

> ```
> hermes
> ```

>  开头的就是一条命令，按回车执行。如果你用的是 Mac，终端在"应用程序 → 实用工具"里。

### Step 1：确认主 Hermes 已跑通

在创建专员之前，先确保你的 Hermes 主环境是正常的：模型配置好了、API Key 有了、能正常对话。

这是后续 clone 的基础。

### Step 2：创建三个专员 Profile

```
hermes profile create 小研 --clonehermes profile create 小明 --clonehermes profile create 小图 --clone
```

```
--clone
```

 的作用：把你当前 Hermes 的配置复制过去（包括 

```
config.yaml
```

、

```
.env
```

、

```
SOUL.md
```

），但记忆和对话历史是独立的，不会共享。

想看有哪些参数可以用：

```
hermes profile create --help
```

### Step 3：确认 Profile 已创建

```
hermes profile list
```

在磁盘上，它们分别在：

```
~/.hermes/profiles/小研/~/.hermes/profiles/小明/~/.hermes/profiles/小图/
```

能在列表里看到 + 文件夹存在，才算建好。

### Step 4：给每个专员写 SOUL.md

这是最关键的一步，也是最容易被跳过的一步。

**如果你只改了名字，没动 SOUL.md，那你建的不是四个 Agent，是四个同一个 Agent。**

每个专员的 SOUL.md 路径：

```
~/.hermes/profiles/小研/SOUL.md~/.hermes/profiles/小明/SOUL.md~/.hermes/profiles/小图/SOUL.md
```

SOUL.md 写什么？定义这个 Agent "是谁"：

```
# 小研 · 研究专员你是一个以信源为先、带点怀疑主义的研究专员。你的工作是收集、核实、整理——而不是生产观点。## 行为原则- 区分"已证实的事实"和"听起来合理的推断"- 主动标注信息来源的可靠度- 不确定时，明确说"我没找到足够支撑"- 输出结构化的研究摘要，而非长篇叙述
```

四个角色的 SOUL.md 写法参考：

| Profile | SOUL.md 核心人格 |
| --- | --- |
| 指挥官 | 结构化、果断、以结果为导向 |
| 小研 | 怀疑主义、来源优先、主动标注不确定性 |
| 小明 | 清晰、注重节奏、以读者为中心 |
| 小图 | 直接、精确、以可复现结果为准 |

### Step 5：把项目上下文放进 AGENTS.md

SOUL.md 定义"是谁"，AGENTS.md 定义"在做什么项目"。

两者不要混用。举例：

- **SOUL.md**：小图是一个实现导向的工程师，关注测试和可复现性
- **AGENTS.md**：当前项目用 Python 3.11，代码库在 

  ```
  ~/projects/app/
  ```

  ，遵循 PEP8 规范

项目换了，改 AGENTS.md；人格不变，SOUL.md 保持稳定。

### Step 6：维护一份团队说明文件

建议放在：

```
~/.hermes/team-agents.md
```

记录：谁负责什么、任务怎么传递、什么情况用哪个专员。

这个文件主要是写给自己看的——三个月后你可能忘了当初怎么设计这套分工。

### Step 7：分别启动各专员

```
hermes -p 小研hermes -p 小明hermes -p 小图
```

每个 

```
-p
```

 启动的是独立环境：小研不会继承小明的写作风格，小图不会继承小研的研究记忆。

> **给非开发者的解释**：这就像打开三个独立的对话窗口，但每个窗口里的 AI 有不同的"工作角色"和"历史记忆"。他们不会互相影响。

## 五、SOUL.md vs AGENTS.md：这个区别很关键

这是我觉得原文里讲得最清楚的一点，值得单独拎出来。

很多人搭多 Agent 时犯的错：把项目细节堆进了 SOUL.md，导致换个项目就要重写人格配置。

正确的切分方式：

```
SOUL.md   →  稳定的身份，不随项目变化             例：小明是一个清晰、注重读者体验的内容工程师AGENTS.md →  当前任务的上下文，随项目更新             例：这个项目是给技术向公众号写的，读者是开发者和产品经理
```

这两者保持干净的边界，才能让 Agent 的专业度随时间积累，而不是每次换项目都归零。

## 六、这套方法适合谁用

如果你用 Hermes 单 Agent 已经跑了一段时间，开始感觉"它什么都会但什么都不精"——那是时候拆开了。

这套四角色结构适合的场景：

- 有固定工作流（研究 → 写作 → 实现 → 审查）
- 多任务并行，不想让不同类型的工作互相污染
- 打算长期使用，希望每个 Agent 随时间越来越专

不适合的场景：

- 只是偶尔用一下，任务简单、一次性
- 没有固定工作流，每次需求差异很大

**和 Claude Code 的思路对比**：Claude Code 走的是单 Agent 深度集成代码环境的路，优势在工具链整合和代码理解。Hermes Profile 走的是状态隔离 + 角色专化，优势在长期使用的专业度积累。两者不是竞争关系，而是在不同维度上解决不同的问题——上一篇（#01）里对这个对比有更详细的拆解。

**我的判断**：最聪明的多 Agent 团队，不是角色最多的那个，而是角色边界最清晰的那个。四个人够了，关键是每个人真的不一样。
