# 周一早上睁开眼，手机上挂着一堆未读消息，其中有一半是各种技术群在转 GitHub 链接。我喝着咖啡刷了一遍，感觉这周开局就没打算让人安静——几个项目一起冲榜，而且话题还挺分散，从 Agent 技能到 TypeScript 换底层，全都在同一天挤进了视野。

下面是今天值得看一眼的东西，不废话，直接进正题。

---

## 1. mattpocock/skills：把自己的 .claude 目录开源了 🛠️

这个项目一上来就吸引了我的注意——作者 Matt Pocock 是 TypeScript 社区的老熟脸，他直接把自己平时用的 Agent 技能集合开了一个公开仓库。

简单说：这是一堆 shell 脚本和 prompt 文件，专门用来告诉 AI 编码助手"你在我这个项目里该怎么工作"。比如代码审查的规则怎么定、提交信息要用什么格式、跑测试之前要检查哪些东西。不是什么黑科技，但实用程度很高。

我自己也在折腾类似的东西，每次换项目都得重新给 AI 讲规矩，这种"可复用的技能包"思路确实省事。Star 数已经破 23K，说明不止我一个人有这个痛点。

---

## 2. microsoft/typescript-go：TypeScript 要换发动机了

微软在悄悄干一件大事：用 Go 重写 TypeScript 编译器。

这个项目现在还是"暂存仓库"状态，25K 星已经说明社区热度不低。逻辑很直接——现有的 TypeScript 编译器是 JS 写的，跑在 Node.js 上，性能有天花板；换成 Go 之后，编译速度理论上有大幅提升空间。

对我们日常开发影响几何？短期内基本感受不到，长期来看如果大型项目的 

```
tsc
```

 时间从 30 秒变成 3 秒，那体感确实完全不一样。掘金这周也有人在讨论"TypeScript 为什么是 2026 年最重要的语言"，和这个项目放在一起看挺有意思的。

---

## 3. GitNexus：不需要服务器，直接在浏览器里跑代码知识图谱

这个项目的定位有点特别：零服务端，所有逻辑都跑在浏览器里，帮你把一个代码仓库的依赖关系、模块调用链做成可交互的知识图谱，还能跑 Graph RAG 查询。

技术上用的是 TypeScript + WebAssembly，把原来要后端撑着的代码分析任务直接搬到前端。30K Stars，看起来确实戳到了"想分析代码但不想搭环境"这个痛点。

我测了一下小项目还可以，大型 monorepo 建议给浏览器多留点内存，不然容易卡。

---

## 4. free-claude-code：薅羊毛的艺术 🆓

这个项目我看了一眼，作者做了一个让你在终端或者 VSCode 里免费跑 claude-code 的方案，支持接 Discord。

具体原理是接了一些免费额度的 API 路由，所以"免费"是有引号的——不是完全没限制，但对于日常轻量试用确实够用。Star 数 13K，足以说明大家对 AI 工具的付费意愿……目前还比较有限。

我个人的立场是：如果真在用，还是买个正经订阅吧，薅羊毛用来入门尝试可以，但别把主力工作流押在这种方案上。

上周 andrej-karpathy-skills 单周暴增 44K 星，这个劲儿还没过。一个
