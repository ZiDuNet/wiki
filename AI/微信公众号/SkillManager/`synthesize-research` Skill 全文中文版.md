# 综合研究

> 如果你看到了不熟悉的占位符，或者需要确认当前连接了哪些工具，请查看 

> ```
> CONNECTORS.md
> ```

> 。

将来自多个来源的用户研究整理为结构化发现与建议。

## 用法

```
/synthesize-research $ARGUMENTS
```

## 工作流

### 1. 收集研究输入

可以接受以下任意组合的研究材料：

- **粘贴文本**：访谈笔记、转录稿、问卷回复、用户反馈
- **上传文件**：研究文档、表格、录音摘要
- \*\*

  ```
  ~~knowledge base
  ```

  \*\*（如已连接）：搜索研究文档、访谈笔记、问卷结果
- \*\*

  ```
  ~~user feedback
  ```

  \*\*（如已连接）：拉取近期支持工单、功能请求、缺陷报告
- \*\*

  ```
  ~~product analytics
  ```

  \*\*（如已连接）：拉取使用数据、漏斗指标、行为数据
- \*\*

  ```
  ~~meeting transcription
  ```

  \*\*（如已连接）：拉取访谈录音、会议摘要与讨论记录

向用户确认他们手头有什么：

- **研究类型**：访谈、问卷、可用性测试、数据分析、支持工单、销售通话记录等
- **来源 / 参与者数量**：一共有多少份材料、多少位参与者
- **研究问题或假设**：是否在验证某个明确问题或假设
- **决策用途**：这份研究最终要支撑什么决策

### 2. 处理研究材料

针对每个来源，提取以下内容：

- **关键观察**：用户说了什么、做了什么、经历了什么
- **引语**：能够说明关键问题的原话
- **行为**：用户实际做了什么，而不是他们口头上说自己会做什么
- **痛点**：挫败、绕路方案、未被满足的需求
- **正向信号**：哪些地方运转良好、哪些时刻让用户感到惊喜
- **上下文**：用户分群、使用场景、经验水平

### 3. 识别主题与模式

应用主题分析法。更详细的方法说明见下方 **研究综合方法论**，其中包含对 thematic analysis、affinity mapping 和 triangulation 的具体指导。

将观察归并为主题，统计每个主题在不同参与者中出现了多少次，并评估影响大小。同时记录彼此矛盾的地方与意外发现。

建立一个优先级矩阵：

- **高频 + 高影响**：最高优先级发现
- **低频 + 高影响**：对特定分群很重要
- **高频 + 低影响**：改善体验质量的机会
- **低频 + 低影响**：记录即可，但降低优先级

### 4. 生成综合结果

输出一份结构化的研究综合结果：

#### 研究概览

- **方法说明**：研究类型、参与者 / 来源数量
- **研究问题**：这次研究希望弄清什么
- **时间范围**：研究是在什么时候进行的

#### 关键发现

对每个主要发现（建议控制在 5 到 8 条）：

- **发现陈述**：用一句清晰的话概括洞察
- **证据**：支撑该发现的引语、数据点或观察，并注明来源
- **频次**：有多少参与者 / 来源支持这一发现
- **影响**：这一发现对用户体验或业务影响有多大
- **置信度**：高（证据强）、中（有指向性）、低（早期信号）

按优先级对发现排序，即按“频次 × 影响”排序。

#### 用户分群 / 人物画像

如果研究揭示出明显不同的用户分群：

- 分群名称与描述
- 关键特征与行为
- 独特需求与痛点
- 若有数据，则估算该分群规模

#### 机会区域

基于发现识别机会区域：

- 哪些用户需求尚未被满足或服务不足
- 当前方案在哪些地方做得不够
- 哪些新能力可以释放价值
- 按潜在影响排序

#### 建议

给出具体、可执行的建议：

- 应该构建什么、调整什么、或继续调查什么
- 每条建议都要对应到具体发现
- 按影响与可行性排序

#### 待解问题

列出这轮研究尚未回答的问题：

- 目前理解中的空白
- 还需要进一步调查的区域
- 建议采用的后续研究方法

### 5. 复核与延展

在生成综合结果后：

- 询问是否有发现需要展开更多细节或换一种表述方式
- 提供进一步产出：人物画像文档、机会地图、研究汇报材料
- 提供针对待解问题的后续研究计划
- 提供产品层面的含义整理，即这些发现应如何影响路线图

## 研究综合方法论

### Thematic Analysis

这是整理定性研究时最核心的方法：

1. **熟悉材料（Familiarization）**：通读全部数据。在编码前先对整体材料形成基本判断。
2. **初始编码（Initial coding）**：系统地过一遍数据。为每条观察、引语或数据点打上描述性标签。编码宁可多一些，后面合并总比事后拆分容易。
3. **发展主题（Theme development）**：将相关编码归并成候选主题。一个主题应该围绕研究问题，概括出数据里真正重要的一类现象。
4. **复核主题（Theme review）**：回到数据本身检查主题。每个主题是否有足够证据支撑？主题之间是否彼此区分？它们能否共同讲出一个连贯故事？
5. **细化主题（Theme refinement）**：清晰定义并命名每个主题。用 1 到 2 句话说明这个主题究竟捕捉了什么。
6. **输出报告（Report）**：将主题整理为带证据支持的发现。

### Affinity Mapping

这是一个协作式整理观察的方法：

1. **记录观察**：将每一条独立观察、引语或数据点写成单独便签
2. **聚类**：依据相似性将相关便签分组，不要预设类别，先看数据自己会聚成哪些类
3. **命名分组**：为每个分组起一个能抓住共同线索的名字
4. **组织分组**：如果出现更高层级的规律，就把多个分组组织成更大的集合
5. **识别主题**：分组及其相互关系将揭示关键主题

**Affinity Mapping 的提示**：

- 每张便签只记录一条观察，不要把多个洞察揉在一起
- 便签可以在不同分组之间自由移动，第一次分组很少就是最优答案
- 如果一个分组过大，往往意味着里面其实混了多个主题，应继续拆开
- 离群点也很重要，不要强行把每条观察塞进某个分组
- 分组过程本身和最终结果同样有价值，因为它能帮助团队建立共享理解

### Triangulation

通过结合多个数据来源来增强发现的可信度：

- **方法三角验证**：同一个问题，用不同方法验证，例如访谈 + 问卷 + 数据分析
- **来源三角验证**：同一种方法，但换不同参与者或分群
- **时间三角验证**：在不同时间点反复观察同一现象

一个同时得到多种来源与多种方法支持的发现，会比只依赖单一来源的发现更扎实。当不同来源之间出现不一致时，这本身也值得关注——它可能揭示出不同用户分群或不同使用情境。

## 访谈笔记分析

### 如何从访谈笔记中提取洞察

对每场访谈，识别以下内容：

**观察**：参与者描述了什么行为、经历或感受？

- 区分行为（他们做了什么）与态度（他们怎么想、怎么感受）
- 记录上下文：什么时候、在哪里、和谁一起、多频繁发生
- 标记绕路方案，这往往是“未满足需求”的伪装形态

**直接引语**：能够有力说明某个问题的原话

- 好的引语应当具体、生动，而不是泛泛而谈
- 归因给参与者类型，而不是姓名，例如“200 人团队的企业管理员”，而不是 “Sarah”
- 引语是证据，不是发现；发现是你对引语意义的解释

**行为与口头偏好之间的差异**：人们实际做的，常常和他们口头想要的不同

- 行为观察通常比口头偏好更有证据强度
- 如果参与者说“我想要功能 X”，但其工作流显示他们从不使用类似功能，就要记录这种矛盾
- 通过真实行为识别他们的真实偏好

**强度信号**：这件事对参与者到底有多重要？

- 情绪语言：挫败、兴奋、无奈
- 频次：他们多常遇到这个问题
- 绕路成本：他们为了绕开问题投入了多少额外努力
- 影响：事情出错时会带来什么后果

### 跨访谈分析

在处理完单场访谈后：

- 寻找模式：哪些观察在多个参与者之间反复出现
- 记录出现次数：每个主题被多少参与者提到
- 识别分群：不同类型用户是否呈现出不同模式
- 找出矛盾：参与者在哪些地方不一致，这往往揭示有意义的分群差异
- 找到意外：哪些结果挑战了你原有的假设

## 问卷数据解读

### 定量问卷分析

- **响应率**：样本有多大代表性？过低的响应率可能引入偏差。
- **分布**：不要只看平均值，也要看回答分布形状。双峰分布（很多 1 分和 5 分）和正态分布（很多 3 分）反映的是完全不同的用户情况。
- **分群分析**：按用户分群拆开回答。总体平均很容易掩盖重要差异。
- **统计显著性**：样本较小时，要谨慎对待那些看起来不大的差异。
- **基准对比**：分数与行业基准或过往问卷相比如何？

### 开放题问卷分析

- 把开放题回复当作迷你访谈笔记来处理
- 为每条回复做主题编码
- 统计不同主题的出现频次
- 为每个主题抽取有代表性的引语
- 特别关注那些出现在开放题里、却没有出现在结构化问题中的主题——这往往是你原本没想到要问的东西

### 常见问卷分析错误

- 只报告平均值，不报告分布。3.5 的平均值可能意味着大家都不冷不热，也可能意味着一半人很喜欢、一半人很讨厌。
- 忽略未回应偏差。没有回复的人可能在系统性地不同于回复的人。
- 过度解读很小的差异。NPS 提升 0.1 分，很多时候只是噪声，而不是信号。
- 把 Likert 量表当作等距数据处理。“非常同意”和“同意”之间的距离，不一定等于“同意”和“中立”之间的距离。
- 在交叉分析中混淆相关性与因果性。

## 结合定性与定量洞察

### 定性—定量反馈回路

- **先定性**：访谈与观察帮助回答“发生了什么、为什么会这样”，并产生假设。
- **再定量验证**：问卷与分析数据帮助回答“影响有多大、涉及多少人”，从而在更大规模上验证假设。
- **再回到定性深挖**：对那些意外的定量发现，再用定性方法继续理解。

### 整合策略

- 用定量数据给定性发现排优先级。如果访谈中出现的某个主题，也在使用数据里影响了大量用户，那它的重要性就更高。
- 用定性数据解释定量异常。留存率下降是一个数字，而访谈可能揭示其原因是 onboarding 改版让人困惑。
- 展示组合证据。例如：“47% 的受访用户表示在 X 上有困难（问卷），而访谈显示其原因在于 Y（定性发现）。”

### 当不同来源互相矛盾时

- 定量和定性来源讲出不同故事并不罕见，这是一种信号，不是错误。
- 检查这种差异是否来自被测量的人群不同。
- 检查口头偏好（问卷）是否与真实行为（分析数据）不一致。
- 检查定量问题本身是否真的测到了你以为它测到的内容。
- 与其简单选边站，不如诚实报告这种差异，并继续调查。

## 基于研究构建人物画像

### 如何建立有证据支撑的人物画像

人物画像应该基于研究数据提炼出来，而不是靠想象捏造：

1. **识别行为模式**：在参与者之间寻找相似的行为、目标与情境簇
2. **定义区分变量**：是什么维度把一个簇与另一个簇区分开来？例如公司规模、技术能力、使用频次、主要使用场景
3. **创建画像档案**：对每个行为簇，整理：

- 名称与简要描述
- 关键行为与目标
- 痛点与需求
- 上下文（角色、公司、所用工具）
- 代表性引语

4. **用数据验证**：你能否用定量数据估算每个画像分群的规模？

### 人物画像模板

```
[画像名称] —— [一句话描述]他们是谁：- 角色、公司类型 / 规模、经验水平- 他们如何发现并开始使用这款产品他们想完成什么：- 主要目标与待完成任务- 他们如何衡量成功他们如何使用产品：- 使用频次与深度- 关键工作流与所用功能- 他们会与这款产品配套使用哪些工具核心痛点：- 最主要的 3 个挫败点或未满足需求- 他们为此发展出的绕路方案他们重视什么：- 一个解决方案中最重要的是什么- 什么会让他们切换产品或流失代表性引语：- 2 到 3 条能够体现该画像视角的原话
```

### 常见人物画像错误

- **人口统计画像**：按年龄、性别、地区定义，而不是按行为定义。对产品需求的预测，行为通常比人口统计特征更有用。
- **画像过多**：3 到 5 个通常是甜蜜区间。再多就很难指导行动。
- **虚构画像**：基于主观假设编出来，而不是基于研究数据。
- **静态画像**：产品和市场变了，画像却从不更新。
- **没有产品含义的画像**：如果某个画像不会改变任何产品决策，它就没有实际价值。

## 机会规模评估

### 估算机会大小

对每个研究发现或机会区域，估算：

- **可触达用户数**：有多少用户可能因解决这个问题而受益？可使用产品分析、问卷数据或市场数据来估算。
- **频次**：受影响用户多久会遇到一次这个问题？每日、每周、每月，还是一次性？
- **严重程度**：问题发生时，对用户影响有多大？是阻断性问题、明显摩擦，还是轻微烦扰？
- **付费意愿**：解决这个问题是否会提升升级率、留存率，或带来新客获取？

### 机会评分

可以用一个简化矩阵来为机会打分：

- **影响**：受影响用户数 × 频次 × 严重程度 = 影响分数
- **证据强度**：我们对这个发现有多大把握？多来源 > 单一来源，行为数据 > 口头偏好
- **战略一致性**：这个机会是否与公司战略和产品愿景一致？
- **可行性**：我们是否现实地有能力去解决它？包括技术可行性、资源可用性、见效时间

### 如何呈现机会规模评估

- 透明说明你的假设与置信度
- 展示计算逻辑，例如：“根据支持工单量，约有每月 2,000 名用户会遇到这个问题。访谈数据显示，其中 60% 认为这是明显阻断。”
- 用区间代替虚假的精确数字，例如“每月影响 1,500 到 2,500 名用户”，而不是“每月影响 2,137 名用户”
- 把不同机会放在一起比较，排出相对优先级，而不只是展示绝对分数

## 输出格式

使用清晰标题与结构化排版。每条发现都应当可以独立成立——读者应该只看任意一条发现，就能理解它的意义，而不必先通读全文。

## 提示

- 让数据自己发声，不要把发现强行塞进预设叙事里。
- 区分用户说了什么与用户做了什么。行为数据通常比口头偏好更有证据力。
- 引语是很有力的证据，应当尽可能充分使用，并注明参与者类型而非姓名。
- 明确标出置信度。来自 2 场访谈的发现更接近假设，而不是结论。
- 数据中的矛盾很有意思，不是麻烦。它们往往揭示出不同用户分群。
- 建议要具体到可以行动。“改进 onboarding” 并不可执行，“在设置流程中加入进度指示器” 才是可执行建议。
- 抵抗把过多主题强行综合到一起的冲动。5 到 8 条强发现，通常好过 20 条弱发现。
