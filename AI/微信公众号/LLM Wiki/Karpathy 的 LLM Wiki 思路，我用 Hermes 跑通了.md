00 / 引子

Andrej Karpathy 在 GitHub 上开源了一份 LLM Wiki 文档。没代码，纯文本思路。但在 HN 上拿了 800+ upvotes。

它解决了一个痛点：我们用 AI 读论文、查资料，往往是"检索完就散"。没有累积，没有结构。

Karpathy 的核心主张是：**不要让 AI 每次检索原始文件。让 AI 持续维护一个 wiki，每读一篇新资料就自动更新、标注矛盾、建立连接。**

这个思路很性感。但怎么落地？

我没从头写代码。我用"两步接力"，在半天内跑通了这条链路。

01 / 第一步：让 Claude Code 搞定基建

我的目标是用 Hermes（一个开源的 AI Agent 框架）来执行这个任务。

但部署 Hermes 需要配环境、装依赖、调网关——典型的脏活。

我没手动搞。直接把 Hermes 的搭建文档丢给 **Claude Code**，告诉它：

"按文档，帮我把环境跑通。"

Claude Code 读文档、写配置、解报错，一次性搞定。

**定性：** 这种一次性、强执行的基建任务，交给 Claude Code 这种"顶级建筑队"最高效。它干完就撤，不留恋。

02 / 第二步：让 Hermes 落地知识库

基建完成后，轮到 **Hermes** 上场。它的任务是长期的知识管理。

我把 Karpathy 的 LLM Wiki gist 地址喂给 Hermes，告诉它： "这是我的领域：AI Agent、无人机运筹学、MKG 项目。按这个思路，帮我建一个知识库。"

接下来，Hermes 开始干活：

1. 1

   **自建结构**：按 gist 里的三层架构（Raw Sources → Wiki → Schema）创建目录。
2. 2

   **自我检查**：对照 Karpathy 的核心思想，检查目录结构有没有跑偏，索引对不对。
3. 3

   **跑测试**：确认"摄入→查询→Lint"三条链路全通。

我只做了一件事：确认它的结构符合我的预期，然后丢进第一篇关于 MKG 的技术文档。它自动读取、提取、归档、建立交叉引用。

**链路通了。**

03 / 为什么这样分工？

有人问：为什么不直接用 Claude Code 做知识库？

答案很直白：**工具没有优劣，只有位置放得对不对。**

**Claude Code = 建筑队。**你给它图纸，它帮你把房子盖起来。能力强，但它是无状态的。房子盖完，它就撤了。它不负责后续的装修、维护、打理。

**Hermes = 施工管家。**它负责在房子里安家，按你的规矩（Schema）整理物品（知识）。它理解你的偏好，能自我纠错，能把新进来的东西归类到已有的体系中。

**把研究员当建筑工用，是浪费。把建筑队当研究员用，是灾难。**

04 / 现状与下一步

现在的状态是：**骨架搭好了，测试通过了。**

我已经把 MKG 的核心文档丢进去测试，Hermes 自动生成了对应的 Wiki 页面，并建立了初步的交叉引用。

接下来的工作很简单：

1. 4

   持续喂给它新的论文和笔记。
2. 5

   观察它的归纳逻辑，微调 Schema。
3. 6

   让它在"整理"的过程中，帮我发现知识盲区。

我不再需要手动创建文件夹、手动写摘要。系统会自己生长。

**核心原则：**

知识的价值不在于你读了多少，而在于你累积了多少。

让 AI 帮你做累积。你负责思考。

05 / 写在最后

这套方案最让我兴奋的，不是省了多少整理时间。

而是我发现了一种新的学习模式：知识不再是静态的笔记，而是一个会自己生长的有机体。

每读一篇新资料，整个知识库都会发生微小的变化——旧的观点被修正，新的连接被建立，隐藏的矛盾被标注出来。

你不再是在"记笔记"。你是在"养一个系统"。

而你要做的，只是持续喂它好的素材，然后看着它自己长大。

系统跑通了，剩下的就是往里填东西。不填，它也不会替你思考。
