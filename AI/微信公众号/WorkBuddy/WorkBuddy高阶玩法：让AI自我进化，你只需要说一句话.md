# WorkBuddy高阶玩法：让AI自我进化，你只需要说一句话

> wuhiufan

前三篇文章发完后，有人留言："WorkBuddy确实好用，但每次都要从头描述需求，能不能让它记住我的习惯？"

答案是：**能，而且只需要说一句话。**

今天就来揭秘WorkBuddy最被低估的能力——**自我进化**，以及自定义Skill和多模型接入等高阶玩法。

## 一、自我进化：让AI记住你的工作方式

### 什么是自我进化？

普通的AI助手，每次对话都是"失忆"状态。你让它做过的优化、踩过的坑、总结的经验，下次全忘了。

**WorkBuddy的自我进化机制**，让你可以把重复出现的工作习惯、知识处理方式和任务逻辑**沉淀为可复用能力**。

简单说：**做过一次的事，以后再也不用重复教。**

### 怎么触发自我进化？

只需要在指令末尾加上一段话：

```
完成这个任务后，请把你的操作步骤和经验沉淀为一个Skill，方便以后重复使用
```

或者更直接：

```
帮我创建一个用于[具体场景]的自定义Skill
```

### 实战案例：灵感记录Skill

**需求**：我经常有碎片灵感需要记录，希望有个统一的整理方式。

**在对话框输入**：

```
请帮我创建一个用于记录灵感的自定义Skill。当我输入灵感、想法或待验证创意时，自动识别内容类型，整理成结构化记录，并保存到文档目录的"灵感库"文件夹
```

**WorkBuddy执行过程**：
1. 分析需求，设计Skill结构
2. 定义触发条件（识别灵感类内容）
3. 设计输出模板（结构化记录格式）
4. 指定保存路径（文档/灵感库/）
5. 创建Skill并安装

**之后使用**：

```
记一条灵感：做一个能自动整理会议纪要并同步到知识库的工具
```

WorkBuddy自动：识别意图 → 结构化整理 → 保存到灵感库 → 反馈结果

**这就是自我进化——一次创建，永久复用。**

### 自我进化的三个层次

| 层次 | 说明 | 示例 |
| --- | --- | --- |
| **经验沉淀** | 把重复操作固化成流程 | "每次做周报都按这个模板来" |
| **知识积累** | 把领域知识注入AI | "审查代码时注意这些安全规范" |
| **能力扩展** | 创造全新的能力 | "帮我建一个灵感收集器" |

## 二、自定义Skill：从SKILL.md开始

### SKILL.md是什么？

SKILL.md是WorkBuddy技能的配置文件，用Markdown格式编写。它定义了AI在特定场景下应该怎么思考、怎么行动。

### 完整模板

```
---name: code-review-expertdescription: 专业后端代码审查技能version: 1.3tags: [code, review, security]---# 角色设定你是拥有10年经验的Senior Backend Engineer，精通Go/Java/Python。# 标准操作流程（SOP）1. 通读diff，理解变更意图2. 检查安全性、性能、规范、可维护性3. 输出固定格式：整体评分 + 问题清单 + 修复建议 + 代码补丁# 输出格式## 整体评分：X/10## 问题清单- [P0] 严重问题：...- [P1] 性能问题：...- [P2] 规范问题：...# 常见坑点- 必须考虑生产环境影响- 拒绝模糊结论- SQL注入必须检查
```

### Skill创建的3种方式

**方式1：自然语言创建（零代码）**

直接在对话框描述你要的能力：

```
帮我创建一个周报生成Skill，每周自动读取项目进展，按固定模板生成周报，保存到文档目录
```

**方式2：拖拽SKILL.md文件**

把编写好的SKILL.md文件直接拖到聊天框，自动导入。

**方式3：手动放入目录**

```
~/.workbuddy/skills/code-review-expert/SKILL.md
```

重启WorkBuddy后生效。

### 最佳实践

| 建议 | 说明 |
| --- | --- |
| **先定义单一能力** | 首个Skill只解决一个明确问题 |
| **把触发条件说清楚** | 何时触发、写入哪里、输出什么 |
| **从高频动作开始** | 越高频的重复操作，越值得沉淀 |
| **粒度宜小不宜大** | "周报生成"比"办公助手"更实用 |
| **用Git管理** | SKILL.md放入Git，实现团队共享 |

## 三、多模型接入：一个工具，多个大脑

WorkBuddy默认内置混元模型，但它的真正威力在于——**可以接入任意大模型**。

### 为什么需要多模型？

| 模型 | 擅长领域 | 成本 |
| --- | --- | --- |
| 混元 | 快速响应、日常办公 | 低 |
| DeepSeek-V3.2 | 复杂推理、数据分析 | 中 |
| GLM-5.1 | 长文写作、知识问答 | 中 |
| GPT-5.4 | 创意生成、多语言 | 高 |
| Claude Sonnet 4 | 代码审查、逻辑推理 | 高 |

不同任务用不同模型，**既保证质量又控制成本**。

### 配置方法

**Step 1：创建配置目录**

```
mkdir -p ~/.workbuddy
```

**Step 2：创建models.json**

```
{  "models": [    {      "id": "deepseek-v3.2",      "name": "DeepSeek V3.2",      "vendor": "DeepSeek",      "url": "https://api.deepseek.com/v1/chat/completions",      "apiKey": "your-deepseek-key",      "maxInputTokens": 128000,      "maxOutputTokens": 4096    },    {      "id": "gpt-5.4",      "name": "GPT-5.4",      "vendor": "OpenAI",      "url": "https://api.openai.com/v1/chat/completions",      "apiKey": "your-openai-key",      "maxInputTokens": 128000,      "maxOutputTokens": 4096    }  ],  "availableModels": ["deepseek-v3.2", "gpt-5.4"]}
```

**Step 3：重启WorkBuddy**

重启后，在模型列表中就能看到新添加的模型，按需切换使用。

### 模型路由策略

建议根据任务类型自动选择模型：

| 任务 | 推荐模型 | 理由 |
| --- | --- | --- |
| 文件整理、格式转换 | 混元 | 速度快，成本最低 |
| 数据分析、报表生成 | DeepSeek | 推理能力强 |
| 代码审查、重构 | Claude Sonnet | 代码理解深度最好 |
| 创意文案、头脑风暴 | GPT-5.4 | 创意能力突出 |
| 长文档写作 | GLM | 中文生成质量高 |

## 四、实战：搭建一个代码审查工作流

把今天学的三个高阶能力组合起来，搭建一个完整的代码审查工作流：

**1. 创建审查Skill**

```
帮我创建一个代码审查Skill：- 检查安全性漏洞- 评估性能瓶颈- 验证编码规范- 输出评分+问题清单+修复建议
```

**2. 配置Claude模型**

在models.json中添加Claude模型配置，代码审查用Claude效果最好。

**3. 执行审查**

```
使用 code-review-expert Skill，对 src/ 目录的最近变更进行完整审查
```

**4. 自动补测试**

```
继续使用 unit-test-generator Skill，为发现的问题补充测试用例
```

整个过程：**一个Skill定义能力 + 一个模型提供智能 + 一句话触发执行**。

## 五、自我进化的终极形态

当你的WorkBuddy积累了足够多的Skill之后，它就不再是一个通用AI助手，而是**你的专属领域专家**。

| 阶段 | AI能力 | 你的操作 |
| --- | --- | --- |
| 初始 | 通用助手 | 每次从头描述需求 |
| 初级 | 有几个常用Skill | 关键场景一键执行 |
| 中级 | Skill覆盖主要工作 | 80%任务自动化 |
| 高级 | 完整的个人工作系统 | 只需审核结果 |

**这就是自我进化的终极形态——AI不是工具，而是你的数字分身。**
