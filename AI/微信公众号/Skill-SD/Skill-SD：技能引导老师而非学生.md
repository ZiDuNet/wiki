"技能直接给学生会破坏探索能力——Sokoban从51.6%崩到20.3%。反直觉设计：技能只给老师，学生通过蒸馏'偷'知识。"



**编者按**：你有没有想过：技能应该直接给学生看，还是只给老师看？传统做法是把技能直接塞给Agent，但实验发现这样做会破坏Agent的探索能力——Sokoban成功率从51.6%崩到20.3%。Skill-SD做了一个反直觉的设计：技能只给老师（Teacher），学生通过蒸馏把老师的知识"偷"过来。结果AppWorld提升14.0%，Sokoban提升10.9%。核心位移：从"直接给技能"到"老师引导+学生蒸馏"。



## 一、Self-Distillation的三个痛点

用Self-Distillation训练Agent有三个经典难题：

痛点1：技能直接给学生破坏探索

传统做法把技能直接塞给Agent，但实验发现这样做会破坏探索能力。Sokoban成功率从51.6%崩到20.3%。

**具体表现**：Agent拿到"推箱子技能"后，不再探索其他解法。遇到新场景时，只会机械套用技能，无法适应变化。探索能力下降，成功率崩塌。

痛点2：蒸馏过程信息丢失

学生通过蒸馏获取老师知识，但蒸馏过程可能丢失关键信息。如何保证学生学会老师的核心能力？

**具体表现**：老师演示"推箱子最优解法"，学生蒸馏后只学会了"推箱子动作"，但没有学会"为什么这样推"。遇到新场景时，学生无法灵活应用。

痛点3：技能条件化设计复杂

技能只在特定条件下有效，如何设计条件化机制让学生在正确场景使用正确技能？

**具体表现**：老师有多个技能（推箱子、跳跃、攀爬），学生如何知道何时用哪个技能？传统方法没有条件化机制，学生随机选择技能，成功率低。



## 二、核心位移：从"直接给技能"到"老师引导"

❌ Before：直接给学生技能

技能塞给Agent → Agent直接使用 → 探索能力被破坏 → Sokoban崩到20.3%

✅ After：老师引导+学生蒸馏

技能只给老师 → 学生观察老师行为 → 蒸馏学习 → 探索能力保留 → Sokoban提升10.9%

**类比**：传统做法像直接给答案，学生只会抄。Skill-SD像老师示范，学生通过观察学会解题思路。



## 三、架构：技能条件化蒸馏三阶段

Skill-SD的完整工作流程：

第一阶段：技能注入（Teacher-only）

技能只给老师注入，学生看不到技能内容。老师使用技能生成高质量行为。

**设计理由**：防止学生直接依赖技能，破坏探索能力。

第二阶段：行为观察（Student观察Teacher）

学生观察老师的输入输出行为，学习老师的决策模式。不学习技能内容，只学习行为模式。

**设计理由**：学生通过观察学会"为什么这样决策"，而不是"技能是什么"。

第三阶段：蒸馏学习（Self-Distillation）

学生通过蒸馏损失函数学习老师的核心能力。蒸馏损失关注"行为相似度"，而非"内容复制"。

**设计理由**：蒸馏学习保留探索能力，同时获得老师知识。



## 四、效果：两个基准测试的对比

|  |  |  |  |
| --- | --- | --- | --- |
| 基准测试 | 传统方法 | Skill-SD | 提升幅度 |
| AppWorld | 36.0% | **50.0%** | +14.0% |
| Sokoban | 20.3% | **31.2%** | +10.9% |
| WebShop | 28.4% | **39.7%** | +11.3% |

**关键洞察**：Skill-SD在三个基准测试上都显著提升。AppWorld提升14.0%，Sokoban提升10.9%，WebShop提升11.3%。证明了"老师引导+学生蒸馏"设计的有效性。



## 五、失败案例：探索能力保留的代价

⚠️ 案例1：蒸馏时间成本高

**场景**：训练一个复杂任务的Agent，老师演示需要100轮，学生蒸馏需要50轮。

**问题**：蒸馏时间远高于直接技能注入。训练成本增加150轮。

**解决方案**：Skill-SD支持"渐进蒸馏"——先蒸馏核心技能，再蒸馏细节技能。减少蒸馏轮数，降低训练成本。

⚠️ 案例2：老师选择依赖人工

**场景**：选择哪个Agent作为老师？不同老师有不同的技能组合和决策风格。

**问题**：老师选择依赖人工判断，不能自动化。选择错误老师，学生学到错误知识。

**解决方案**：Skill-SD支持"多老师蒸馏"——学生从多个老师学习，综合不同老师的优点。减少单老师依赖风险。



## 六、批判分析：蒸馏设计的边界

批判1：蒸馏损失设计复杂

蒸馏损失关注"行为相似度"，但如何定义相似度？不同任务有不同的相似度度量。

**更深层问题**：蒸馏损失是"任务特定"的——需要为每个任务设计专门的蒸馏损失函数。

批判2：探索能力保留有限

Skill-SD保留探索能力，但保留程度有限。学生仍会受到老师行为的影响，探索范围受限。

**更深层问题**：探索能力和学习能力是矛盾的——学习能力强，探索范围窄；探索范围广，学习能力弱。

批判3：技能迁移困难

学生学到的技能能否迁移到新任务？实验发现迁移效果有限——学生只学会了特定任务的行为，没有学会通用技能。

**更深层问题**：蒸馏学习是"行为模仿"，不是"能力抽象"。学生模仿行为，但没有理解原理。



## 七、可迁移价值：三个核心设计模式

✅ 1. 老师引导 Pattern

技能只给老师，学生通过观察学习。防止学生直接依赖技能，保留探索能力。

**迁移场景**：多Agent训练场景——高级Agent作为老师，初级Agent作为学生，通过观察学习。

✅ 2. 蒸馏学习 Pattern

学生通过蒸馏损失学习老师行为。关注"行为相似度"，而非"内容复制"。

**迁移场景**：模型压缩场景——大模型作为老师，小模型作为学生，蒸馏学习减少参数量。

✅ 3. 渐进蒸馏 Pattern

先蒸馏核心技能，再蒸馏细节技能。减少蒸馏轮数，降低训练成本。

**迁移场景**：复杂技能训练场景——分阶段蒸馏，逐步提高技能复杂度。



## 八、总结

"技能直接给学生会破坏探索能力——Skill-SD的反直觉设计：技能只给老师，学生通过蒸馏'偷'知识。"

Skill-SD的核心创新是**技能条件化蒸馏**——不是直接给学生技能，是老师引导学生自学。反直觉设计保留探索能力，AppWorld提升14.0%，Sokoban提升10.9%。适合需要训练Agent使用技能的场景，但蒸馏设计有边界：老师选择、蒸馏损失、技能迁移都需要精心调参。后续研究方向：多老师蒸馏、自适应蒸馏损失、跨任务技能迁移。
