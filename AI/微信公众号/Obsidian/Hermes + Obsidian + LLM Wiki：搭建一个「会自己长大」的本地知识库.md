你可能遇到过这些问题。

推特上看到一篇好文，一顿复制粘贴存进 Notion。过了三个月想找回那个概念，翻了半天找不到。

Notion 里存了几百篇笔记，但每篇笔记之间是孤立的。你根本不知道「Agent」这个概念在其他所有地方出现过。

每次问 AI 问题，它都从零开始搜索、临时拼凑答案。上周研究过的内容，今天再问，它又从头来过。Token 废掉一半，回答质量还不稳定。

更要命的是——你的笔记存在别人的服务器上。哪天服务关了，数据就没了。

2026 年春天，一个由 Karpathy 提出理念、Nous Research 落地的方案正在快速走红：**Hermes Agent + Obsidian + LLM Wiki**。

一句话概括：**你把文档丢给 AI，AI 自动整理成结构化的知识网络，本地存储，双向链接，知识不断积累、自我生长。**

---

## RAG 的根本问题：每次都在失忆

在理解这套方案之前，先搞清楚它要解决什么问题。

大多数人用 LLM 处理文档的方式叫 **RAG（检索增强生成）**：把文件丢进去，LLM 查询时检索相关片段，拼起来生成回答。NotebookLM、ChatGPT 文件上传、各种企业知识库产品，底层都是这套。

RAG 能用。但它有一个根本性的问题——**没有积累**。

每次你问一个问题，LLM 都是从零开始找碎片、拼答案。你上周研究过的、上个月分析过的，它全忘了。就像一个每天上班都失忆的同事，你给他交代过的事情，第二天又要重新说一遍。

**RAG 是「被动检索」——你问了才找，找不到就像不存在。**

---

## Karpathy 的反转方案：让 LLM 养一个 Wiki

Karpathy 的思路正好反过来。不是查询时临时检索，而是让 LLM 增量构建并维护一个持久化的 Wiki。

每加入一份新资料，LLM 不是简单地存起来等着以后检索。它会：

•读这份资料，提取关键信息

•把新知识整合进已有的 Wiki 里

•更新实体页面、修订主题摘要

•标记新旧数据的矛盾

•补充交叉引用

知识是**「编译一次，持续维护」**的，不是「每次查询重新发现」的。

Karpathy 自己的用法很形象：**Obsidian 是 IDE，LLM 是程序员，Wiki 是代码库**。他在一边开着 Claude Code 或 Codex，一边开着 Obsidian。LLM 在那边改 Wiki，他在 Obsidian 里实时看结果——点链接、看关系图、读更新后的页面。

## 三层架构：分工极其清晰

这套方案的核心是一个三层结构：

### 第一层：Raw Sources（原始资料）

收集的文章、论文、图片、数据文件。这些是**只读的**——AI 只能读不能改，是信息源头。你丢进去的原始内容永远保留，不会被覆盖。

### 第二层：Wiki（知识库）

由 AI 生成和维护的 Markdown 文件目录，包含：

•**摘要页**：每份来源的一句话总结

•**实体页**：人物、工具、项目

•**概念页**：方法论、原理

•**对比分析**：不同方案、工具的横评

•**综述**：跨文档的综合分析

这一层**完全由 AI 负责**。它创建页面、更新页面、维护交叉引用、保持一致性。你只管读，它负责写。

### 第三层：Schema（配置文件）

一份告诉 AI 这个 Wiki 怎么组织、有什么规范、各种操作该怎么做的文档（比如 

```
SCHEMA.md
```

 或 

```
CLAUDE.md
```

）。你和 AI 一起慢慢迭代这份配置，找到最适合你领域的工作流。

三层设计的好处：**原始资料保真不动、Wiki 由 AI 全权维护、配置文件控制行为规范**。职责清晰，不容易搞乱。

---

## 三大核心操作

### 摄入（Ingest）

往原始资料里丢一份新文档，让 AI 去处理。它读完之后：

1写摘要页

2更新索引

3更新所有相关的实体页和概念页

一份资料可能会触发十几个 Wiki 页面的更新。不同文档里提到的同一个概念，会被关联到同一个 Wiki 节点上。

### 查询（Query）

向 Wiki 提问。AI 搜索相关页面，读完综合回答，带引用。

关键一点：**好的回答可以反向存回 Wiki**。你做过的分析、发现的关联、对比的结论，这些不该消失在聊天记录里，应该沉淀到知识库中。

### 审查（Lint）

定期让 AI 对 Wiki 做健康检查：

•找矛盾

•找过期信息

•找孤儿页面（没有入链的页面）

•找缺失的交叉引用

这个操作让 Wiki 在不断生长的同时保持健康。

## Hermes Agent：自动化执行引擎

有了方法论，谁来干活？答案是 Hermes Agent。

Hermes Agent 是 Nous Research 开发的自主 AI 代理。它最大的特点是**内置学习循环**，能从经验中创建技能、改进技能。

在这套知识管理工作流里，Hermes 承担的功能是**自动化执行引擎**。它内置了 

```
llm-wiki
```

 skill，可以直接按 LLM Wiki 的文件结构规范操作知识库。

这意味着什么？

你不需要手动创建文件夹、整理笔记、添加双向链接。你只需要告诉 Hermes「把这篇文章写入知识库」，它就会自动：

•提取文档中的关键实体（人物、工具、项目）

•提取核心概念（方法论、技术原理）

•创建结构化的 Markdown 文件

•添加 

```
[[双向链接]]
```

 连接相关概念

•更新知识库索引和日志

全程不需要你动手。

### 两条铁律

Hermes 有一个非常重要的使用规则——**只有当你明确要求的时候，它才会操作知识库**。

**规则一：说「写入知识库」，Hermes 来整理。** 当你有文档需要管理，加上这句话，Hermes 自动提取、创建、关联、索引。

**规则二：说「结合知识库」，Hermes 来检索。** 当你需要基于知识库回答问题，加上这几个字，Hermes 才会去检索。日常的普通对话，它不会主动去读你的知识库。

这样做的好处：**知识库不会被无关的对话污染**。每次检索的结果也更精准。

## Obsidian：知识网络展示层

Obsidian 是一款免费的本地双向链接笔记工具，跨 Windows、Mac、Linux 三平台。

它最核心的特点是**双向链接**。在笔记里输入 

```
[[某个概念]]
```

，如果这个页面存在，点击就能跳转。如果不存在，点进去就会创建它。

但真正让它不可替代的，是 **Graph View**——把所有笔记和它们之间的链接关系可视化成一张图。一眼就能看到知识结构，哪些节点是孤岛，哪些是枢纽。

**用法很简单**：把 Wiki 目录作为 Vault 拖进 Obsidian，你就拥有了一个由 AI 精心整理过的知识库。双链网络自由浏览，Graph View 看关联强度，全文搜索找内容。所有内容都是纯 Markdown，可以在任何工具之间迁移。

## 完整工作流：从导入到展示

把三个工具串起来看，整个流程是这样的：

**第一步**：你告诉 Hermes「把这篇 AI 写小说的文章写入知识库」。

**第二步**：Hermes 通过内置的 llm-wiki skill，自动读取文档、提取实体和概念、创建结构化 Markdown、添加双向链接、更新索引和日志。

**第三步**：文件按 LLM Wiki 规范自动生成——

```
raw/sources/
```

 存原始文章，

```
wiki/entities/
```

 存实体文件，

```
wiki/concepts/
```

 存概念文件，

```
index.md
```

 是知识库索引，

```
log.md
```

 是更新日志。

**第四步**：打开知识库目录拖进 Obsidian，双向链接网络可以自由浏览，Graph View 可以看到知识点之间的关联。

**第五步**：无限循环。每次导入新文档，知识网络都会自动更新。已有的页面会被补充新信息，矛盾会被标注，同一概念会被关联到同一个节点。

久而久之，知识库会越来越准确，越来越丰富。

## 为什么是「本地」？

这套方案一个很重要的选择是——**所有数据都在本地**。

Wiki 只是本地一个 Markdown 文件目录。没有向量数据库，没有 embedding pipeline，没有云端依赖。不需要部署任何额外基础设施。

这意味着：

•数据永远属于你自己

•不用担心服务关停、数据丢失

•可以用任何工具读写（VS Code、Vim、Obsidian……）

•规模小时靠 

```
index.md
```

 就够了，大了可以上 

```
qmd
```

——一个本地搜索工具，混合 BM25 和向量搜索，全部跑在本地

## 能用在什么场景？

**深度研究**：花几周甚至几个月研究一个课题，每篇论文读完就摄入，Wiki 自动更新综述和交叉引用。到最后你手里有一个完整的知识体系，不是一堆散落的笔记。

**读书**：每读完一章就摄入，AI 自动建角色页、主题页、情节线索页。读完整本书，你就有一个个人 Wiki。

**团队知识库**：Slack 讨论、会议纪要、项目文档都可以喂进去，AI 帮你维护一个永远更新的内部 Wiki。没有人愿意做的知识库维护工作，交给 AI。

**个人成长**：把日记、播客笔记、文章摘要都喂进去，AI 帮你建一个结构化的自我认知图谱。

## 思考：这不是工具升级，是认知方式的升级

这套方案最有价值的地方，不是省掉了一笔笔记软件的钱，而是**解决了知识积累的根本问题**。

RAG 模式下的知识库，本质上是一个「更好的搜索引擎」。而 LLM Wiki 模式下，知识库是一个**活的、会生长的有机体**——它在不断摄入、编译、关联、修正。

区别在哪？

搜索引擎模式下，知识是静态的，每次使用都要重新检索。而活的有机体模式下，知识是动态积累的——旧的被修订，新的被整合，矛盾被标记，关联被建立。

**使用初期差距不明显，但随着资料量增大，差距会越来越大。** RAG 的回答质量取决于检索质量，检索不到的信息就像不存在。而 Wiki 里的交叉引用早就建好了，矛盾早就标记了，综合分析早就写好了。

> Karpathy 有一句话说得很精准：「Wiki 是一个 persistent, compounding artifact（持久的、会复利的制品）。」

**复利**——这才是 LLM Wiki 和 RAG 之间最本质的区别。
