你用 Obsidian 记笔记，但任务管理靠什么？

很多人的答案是：直接在笔记里写 

```
- [ ] 待办
```

，或者单独建一张「任务池」笔记。凑合着用，时间久了，问题就出来了——

任务散落在各处，想找找不到；想看「这周有哪些待办」，只能一篇篇翻；循环任务（比如每周一提交周报）原生不支持；日期格式不统一，5月12日和2026-05-12混写，查询根本筛不出来。

今天介绍三款插件，**Tasks + Kanban + Day Planner**，分别解决三个问题：全局任务索引、项目进度可视化、一天的时间规划。

---

## 一、Tasks：跨笔记的任务索引系统

Tasks 在你**现有笔记基础上**，给所有复选框装了一个索引系统。它扫描知识库里所有 

```
- [ ]
```

，你通过查询代码块用日期、标签、状态等条件筛选任务。

### 安装后必做的两件事

**替换复选框快捷键。** Obsidian 默认 

```
Ctrl/Cmd + Enter
```

 切换复选框状态。装完 Tasks 后，在设置 → 快捷键里，把「Toggle checkbox status」替换为 **Tasks: Toggle Done**。每次完成任务，任务自动标记完成并写入 

```
completion
```

 日期，后续可用 

```
done date
```

 查询完成时间。

**设置全局过滤器（可选）。** 在 Tasks 设置 → Global Filter 里填入 

```
#task
```

。

这样只有带 

```
#task
```

 标签的笔记，里面的复选框才会进入 Tasks 索引。否则你随手写的「要不要加配图」也会混进来，查出来的结果全是噪音。

> **实测：** 我装了之后第一件事就是设全局过滤器。不设的话，连写在这篇笔记里的「思考要不要加个配图」这种临时任务都会被索引进来，全局查询结果全是噪音。

### 任务语法：三个日期符号

Tasks 在原生复选框语法上加了三个日期符号：

```
- [ ] 写周报 📅 2026-05-15- [ ] 提交方案 🔁 every Monday- [ ] 客户回访 ⏳ 2026-05-10
```

- ```
  📅
  ```

   到期日（due date）—— 到这一天需要完成
- ```
  ⏳
  ```

   计划日（scheduled date）—— 从这一天开始可以执行
- ```
  🔁
  ```

   循环任务（recurring）—— 按指定周期自动生成下一条

循环任务语法：

- ```
  🔁 every day
  ```

   每天
- ```
  🔁 every Monday
  ```

   每周一
- ```
  🔁 every weekday
  ```

   每个工作日
- ```
  🔁 every month on the 1st
  ```

   每月1号

### 任务查询代码块

在任意笔记里插入：

```
not donedue before 2026-05-18limit 20sort by due
```

这行代码查的是：**所有未完成、5月18日前到期、按时效排序的前20条任务**。无论这些任务散落在哪篇笔记，查询结果统一展示，点击跳转到源文件。

**常用查询条件：**

| 查询条件 | 含义 |
| --- | --- |
| ``` not done ``` | 未完成的任务 |
| ``` done ``` | 已完成的任务 |
| ``` due before 2026-05-15 ``` | 到期日晚于指定日期 |
| ``` due after today ``` | 今天之后才到期的 |
| ``` starts before today ``` | 计划日已到但未完成的 |
| ``` tag contains #项目 ``` | 包含特定标签 |
| ``` path includes 项目A ``` | 在特定文件夹或笔记里 |
| ``` sort by due reverse ``` | 按到期日倒序（最紧急的排前面） |
| ``` group by filename ``` | 按所属笔记分组显示 |

**查询分组示例：** 

```
group by due
```

 会把所有任务按到期日分组，今天到期、明天到期、本周到期一目了然。

**进阶：done date 查询。** Tasks 自动记录完成时间，用 

```
done date after 2026-05-01
```

 可以查到所有5月1日后完成的任务——这是周报复盘的基础数据。

**适合谁：** 多项目并行、任务散落在各篇笔记里、需要在全局视角汇总的人。

**读者今天可以试的事：** 装上 Tasks，把 

```
Ctrl/Cmd + Enter
```

 替换为 

```
Tasks: Toggle Done
```

，然后在任意笔记里加一条带 

```
📅
```

 到期日的任务，第二天查一下 

```
due before tomorrow
```

——你会立刻感受到「散落任务被集中看到」的感觉。

## 二、Kanban：Markdown 驱动的看板

Tasks 是数据库，Kanban 是可视化界面。它把 

```
.md
```

 文件渲染成看板视图：列是阶段，卡片是任务，支持拖拽切换状态。关键是**所有数据仍然是纯 Markdown**，不存在锁定，导出到其他工具完全可用。

### 创建看板

新建 

```
.md
```

 文件，填入：

```
```kanban - [ ] 待办 - [ ] 进行中 - [x] 已完成 ```
```

命令面板执行 **Open as Kanban**，或右上角「打开方式」切换到 Kanban 视图。

### 在看板里增删改

**新增卡片**：在任意列加一行 

```
- [ ] 卡片标题
```

，源文件自动更新。

**拖拽切换状态**：把卡片从「待办」拖到「进行中」，源文件里对应格式自动变化，不用手动改 Markdown。

**列可以自定义流程**——不只是 To Do / Doing / Done，可以是你的实际项目阶段：

```
需求确认 → 设计稿 → 开发中 → 测试 → 上线交付
```

**卡片可加双向链接和日期**：

```
- [ ] [[项目A]] 需求评审- [ ] 设计评审 📅 2026-05-16
```

```
[[双向链接]]
```

 关联项目笔记，

```
📅
```

 触发 Tasks 日期感知。

> **实测：** 我用看板管公众号选题流程，四列：候选 → 写作中 → 待发布 → 已发布。每周开一次看板，把候选选题拖进「写作中」，比在笔记里划正字直观多了。但要注意——**Kanban 目前在寻找新维护者**，核心功能稳定，如果你对长期维护有顾虑，可以继续往下看，用 Tasks 查询代替看板做进度管理。

![](assets/img_a45e0cab4632.png)

**适合谁：** 习惯看板思维、需要在多个项目间快速切换、不想因为看板离开 Obsidian 的人。

**读者今天可以试的事：** 新建一个 

```
.md
```

 文件，贴进上面的 kanban 代码块，用命令面板执行 

```
Open as Kanban
```

——30秒看到效果。然后把随手记在笔记里的待办，复制成卡片扔进看板。

## 三、Day Planner：时间线视角的一天

Tasks 解决「有哪些任务」，Kanban 解决「项目进度如何」，Day Planner 解决**今天的时间怎么安排**。它把你的每日笔记渲染成一条时间线，状态栏实时显示当前时间点。

### 安装前提

Day Planner 依赖 **Dataview 插件**。先确保 Dataview 已安装启用，再装 Day Planner。

### 时间块语法

在每日笔记里这样写：

```
- [ ] 09:00 - 10:00 写文章大纲- [ ] 10:30 - 11:30 客户沟通- [ ] 14:00 - 15:00 团队周会
```

Day Planner 把这段文字渲染成一条横向时间线，每个块可点击、可拖拽排序。

关键是：块里的 

```
- [ ]
```

 同时也是 Tasks 可索引的任务。在时间块里写任务，这个任务会自动出现在 Tasks 全局查询里，不用重复录入。

### 打开时间线视图

命令面板执行 **Show Timeline**，或左下角状态栏点击时间线图标。

### 三个核心功能

**迷你时间线**：左下角状态栏实时显示当前时间点。点击展开侧边面板，随时看到今天的时间安排。

**多日视图**：执行 **Show multi-day planner**，一个面板同时看多天的时间块，做周计划时预览整周节奏。

**日历同步**：在设置 → Calendar Sync 里填入 ICS 链接，可从 Google Calendar、iCloud、Outlook 导入日程事件——日历里的会议自动出现在时间线上，不用重复录入。

ICS 链接获取：Google Calendar → 设置 → 日历导出 → 复制「公开日历的 ICS 链接」。

### 与 Tasks 联动

在每日笔记里写：

```
```tasks not done due today sort by due ```
```

Day Planner 把今天到期的 Tasks 任务渲染到时间线末尾——手动日程和自动任务一个视图看到。

> **实测：** 日历同步功能用起来比预想的顺。把我工作日历同步进来后，早上打开 Obsidian，会议和任务同时出现在时间线上，不用在日历和笔记之间来回切换。但要注意，**ICS 同步有时差**，刚新建的日程可能几分钟后才出现在 Day Planner 里。

![](assets/img_760447a8e185.png)

**适合谁：** 有固定日程、需要日视角规划时间、对工具切换有痛感的人。

装好 Day Planner 后，在今日笔记里写三个时间块（哪怕是假的），执行 

```
Show Timeline
```

——第一次看到时间线的感觉，会让你想重新规划今天。

## 四、三件套组合工作流

三个插件各管一个维度，搭配使用覆盖任务管理完整场景。

**早上：Day Planner 做日计划。** 打开今日笔记，用时间块写好今天的日程。时间线显示全天节奏，会议和任务同时看到。

**白天：Kanban 管项目进度。** 每个项目一张看板文件，打开看板拖拽卡片更新状态。临时遇到新任务，在对应笔记里用 Tasks 语法写，它自动进入全局索引，不用切换工具。

**随时：Tasks 查全局汇总。** 周五下午想看这周完成情况：

```
```tasks done date after 2026-05-05 sort by done group by filename ```
```

本周完成的所有任务，按笔记分组——周报素材，5秒生成。

**Templater 模板自动化。** 配合 Templater，新建每日笔记时自动生成时间块格式，不用每天手动写结构：

```
--- 创建时间: <% tp.date.now("YYYY-MM-DD") %> 标签: [打卡/日期/<% tp.date.now("YYYY-MM") %>] ---  # <% tp.date.now("YYYY-MM-DD") %> 日计划  - [ ] 09:00 - 10:00 - [ ] 10:00 - 11:00 - [ ] 14:00 - 15:00 - [ ] 15:00 - 16:00
```

三个插件不要同时装。按顺序来：今天只装 Tasks，在旧笔记里找一条带日期的任务，测试 

```
due before tomorrow
```

 查询——这是整个工作流的起点。感受好的话，明天再加 Kanban，后天加 Day Planner。

## 五、选型建议

| 你的需求 | 推荐 | 原因 |
| --- | --- | --- |
| 任务散落在多篇笔记，需要全局汇总 | Tasks | 查询语法最强大，筛选灵活 |
| 习惯看板管理项目进度 | Kanban | 可视化直观，纯 Markdown |
| 需要日视角的时间规划 | Day Planner | 时间线视图 + 日历同步 |
| 以上三个都要 | 三件套组合 | 覆盖全局/项目/日三个维度 |

**最小起步**：从 Tasks 开始。不改变写笔记习惯，装上就能用全局查询功能解决「任务找不到」的核心痛点。

---

## 总结

Obsidian 原生复选框能凑合用，但三个痛点绕不开：任务散落无法汇总、无法追踪循环任务、日期格式不统一无法筛选。

Tasks：全局查询 — 散落在各篇笔记的任务，一个查询搞定

Kanban：项目看板 — 拖拽切状态，Markdown 驱动

Day Planner：时间块 — 日视角的时间线视图 + 日历同步

三件套配合 Templater 模板，早上 Day Planner 做日计划，白天 Kanban 管项目，Tasks 做全局汇总。Obsidian 不只是笔记工具，还是完整的个人任务管理系统。
