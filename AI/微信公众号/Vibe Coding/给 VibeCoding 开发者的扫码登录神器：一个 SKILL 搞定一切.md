## 1. 为什么个人开发者接扫码登录这么难？

在说解决方案之前，有必要先把问题看清楚。

1. 1. 注册开放平台账号
2. 2. 完成企业认证（需要营业执照等资质）
3. 3. 等待审核
4. 4. 创建一个应用并通过审核（需要有已上线的 App 或网站）
5. 5. 将 App 或网站累计用户数做到 1000 以上
6. 6. 申请登录能力

对于一个个人开发者来说，以上每一步都可能是一堵墙。企业资质是一堵，1000 用户门槛是另一堵。不少人选择绕过这条路，直接用第三方方案——但这些方案要么体验差（扫码需要跳浏览器），要么不稳定（服务没有保障），要么接入成本高（自己搭一套授权服务器）。

而 DreamAuth 的出现，就是来解决这个问题的。

---

## 2. DreamAuth 是什么？

DreamAuth 本质上是一个**第三方扫码登录中转服务**。它已经帮你完成了与生态授权平台的交互，你只需要接入它提供的三个 API，就能让自己的应用拥有扫码登录能力。

它的核心思路非常清晰：

**把复杂的授权，封装成三个简单的 HTTP 调用。**

用户扫二维码、确认授权、获取 openid——这些原本需要你深度对接 API 才能完成的工作，DreamAuth 全部帮你处理了。你只需要：

1. 1. 调用 API 创建扫码会话，获取二维码
2. 2. 在前端展示二维码
3. 3. 轮询状态，确认用户已授权
4. 4. 获取授权结果（openid），在你自己后端建立用户账号

这就是整套流程的全部内容。

## 3. 三步走：DreamAuth 的完整接入架构

DreamAuth 的接入架构分为三层，理解清楚这三层，你就掌握了整个方案的核心。

### 第一层：DreamAuth 小程序

用户在自己的里搜索并打开 **DreamAuth** 小程序。这是你在 DreamAuth 应用中心创建的每一个应用都会对应的授权入口。用户在扫码后会看到授权确认页面，点击确认后授权就完成了。

这一步不需要你做任何开发，全部由 DreamAuth 平台负责。

### 第二层：DreamAuth 开放 API

DreamAuth 暴露了三个标准化的开放 API，你的后端通过签名请求来调用它们：

**第一步：创建扫码会话**

```
POST /api/open/scan-login/session/create
```

你需要传入业务标识（bizCode、bizState、targetType），以及二维码有效期（最长 300 秒）。平台会返回一个 

```
sessionNo
```

 和一张二维码图片的 Base64 数据。

**第二步：轮询授权状态**

```
GET /api/open/scan-login/session/status?sessionNo=...
```

这个接口会返回当前的授权状态：

- 状态 1：等待扫码
- 状态 2：已扫码，等待确认
- 状态 3：已授权，可以获取结果
- 状态 4：已取消
- 状态 7：已过期

前端每 2 秒轮询一次，直到状态变为 3。

**第三步：获取授权结果**

```
POST /api/open/scan-login/session/result
```

传入 

```
sessionNo
```

，服务端会返回用户的 

```
openid
```

、授权凭证 

```
authToken
```

 以及授权时间等信息。你用自己的 

```
openid
```

 在本地数据库建立或查找用户账号，然后签发你自己的登录凭证（JWT 或 Session），返回给客户端。

整个过程中，用户的 openid 只在你的后端流通，不暴露给前端。

### 第三层：你自己的后端

DreamAuth 的 API 签名采用 **MD5(Path|Method|Timestamp|Nonice|PayloadJson|SecretKey)** 格式，所有凭证（AK/SK）都只存在你自己的后端。签名逻辑、用户账号绑定、你自己系统的登录凭证发放，全部由你自己控制。

DreamAuth 负责的是：二维码生成、扫码授权流程、openid 交换。

你自己负责的是：用户数据管理、会话管理、业务逻辑。

这正是这套方案的核心价值——**把登录的复杂性留给自己，把实现细节交给平台**。

## 4. 关键细节：请求签名规范

虽然 DreamAuth 把 API 设计得很简洁，但有一个地方特别容易出错：请求签名。

签名公式如下：

```
MD5(大写HTTP方法 | 请求路径 | 时间戳 | 随机字符串nonce | 请求体JSON | SecretKey)
```

几个必须注意的点：

**时间戳偏差不能超过 5 分钟**。如果服务器时间和 DreamAuth 服务器时间差太多，请求会直接被拒绝。建议使用 NTP 同步服务器时间。

**GET 请求的签名也有讲究**。创建会话（POST）和获取结果（POST）都是签名请求体本身，但查询状态（GET）虽然 HTTP 上是查询参数，它的签名 payload 却是 

```
{"sessionNo": "SL..."}
```

——也就是一个 JSON 字符串，而不是空字符串。这一点非常容易出错。

**SecretKey 绝不离开后端**。无论你的前端是什么形态——Web、移动 App、桌面客户端——SecretKey 只能存在于你的服务器上。所有对 DreamAuth API 的调用，都必须通过你自己的后端中转。

## 5. 多端支持：Web / H5 / App / PC / 桌面

DreamAuth 的扫码登录流程在不同端的表现完全一致，区别只在前端展示方式：

**Web 和 H5**：最标准的场景。PC 浏览器展示二维码，用户掏出手机扫码，手机上确认授权，浏览器轮询得到登录成功。整个过程用户在两个屏幕间切换，体验流畅。

**移动 App 内嵌 H5**：如果在手机浏览器里打开，也有办法处理——可以显示一串 scene 码，让用户在 DreamAuth 小程序里手动输入完成授权，不需要真正扫码。

**原生移动 App**：和 Web 一样，App 请求后端创建 session，展示二维码（可以是第二台设备扫码，也可以是大屏幕投屏），后端轮询确认后完成登录。凭证同样存在 App 的后端服务里，不在 App 包里。

**PC 和桌面应用**：这是 DreamAuth 最舒服的场景之一。桌面应用展示二维码，后台每几秒轮询状态，用户拿出手机扫码确认，应用拿到登录结果——体验和原生桌面 App 的登录完全一致。

## 6. 一个 SKILL，让 AI 直接学会集成

到目前为止，我们描述的都是手动接入的流程。但实际上，这个项目真正独特的地方在于——它提供了一个 **AI Coding Skills**。

简单来说，Skills 是一组结构化的指令文件，告诉 AI 编程工具（比如 Claude Code）：

- 什么时候应该使用这套登录方案
- 需要向开发者询问哪些配置信息
- 完整的 API 签名逻辑怎么写
- 各端集成的注意事项是什么
- 安全规范和常见错误

也就是说，当你告诉 AI「我想给我的项目加上扫码登录」，AI 会自动调用这个 Skill，理解你的业务场景，选择合适的接入路径，生成完整的集成代码。你甚至不需要知道签名算法是怎么工作的——AI 会帮你写好。

这正是 VibeCoding 时代的开发方式：**你描述需求，AI 负责实现**。身份认证这种需要踩不少坑才能做对的模块，尤其适合用这种方式来处理——你不需要成为安全专家，AI 可以替你把关所有细节。

## 7. 安全规范：这些红线不能碰

虽然 DreamAuth 帮你封装了很多复杂性，但在安全层面有几条红线是你必须自己守护的：

**SecretKey 只能存在于后端**。这条原则没有任何例外。无论是 Web 前端代码、移动 App、桌面可执行文件——所有这些都会被人反编译或访问到，只有后端服务是可信的环境。

**每个请求使用新的 nonce**。随机字符串 nonce 是防重放攻击的关键，不要复用。

**sessionNo 是临时句柄**。它只在一段短时间内有效，过期后即废弃，不要用它做持久化标识。持久化标识是 openid。

**结果只消费一次**。获取授权结果时使用 

```
consume: true
```

，确保同一个登录会话只能被处理一次，防止重放。

**发行你自己的登录凭证**。DreamAuth 返回的 authToken 是平台端凭证，你需要用它换成本地账号，然后发行自己的 JWT 或 Session Token 给客户端。不要把 DreamAuth 的凭证直接当作用户登录态。

## 8. 快速开始：你的第一步

如果你现在就想给项目加上扫码登录，建议按以下路径走：

**第一步**，安装 DreamAuth Skills 到你的 AI 编程工具：

```
npx skills add https://github.com/guangyingzhimeng/dreamauth-open-platform --skills dreamauth-open-platform
```

安装完成后，AI 工具就自动学会了 DreamAuth 扫码登录的完整集成方法。

**第二步**，在 DreamAuth 小程序的应用中心，创建一个新应用，获得 

```
appCode
```

、

```
accessKey
```

、

```
secretKey
```

 三件套。

**第三步**，在 AI 编程工具中告诉它「我要接入扫码登录」，然后把三件套配置到后端环境变量里。让 AI 为你的项目生成登录页面和后端接口，然后根据 integration checklist 逐项验证。

整个过程，一个熟练的开发者大约需要 1-2 小时。你甚至不需要完全理解签名算法——AI 会帮你把每个细节处理好。
