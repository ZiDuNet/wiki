花了三个月，测试了二十多个AI编程工具。

总结文档、生成方案、拆解任务，这些AI都能干了。

但最后一步永远卡住：交付物是一份Markdown，内容清清楚楚，拿去分享、汇报、演示，还差一步。

直到我刷到这个项目。

**guizang-ppt-skill**。不到一个月，GitHub直接冲到10.6k Star、845 Fork，v1.1.0。主题很明确：让AI Agent不只是输出文字，还能把一份资料直接变成可演示的横向翻页HTML页面。

我研究了三天，把它的方法论拆出来了。

---

## 它到底是什么？

一句话：**一套给AI Agent用的演示稿Skill，生成单文件HTML横向翻页PPT**。

不是传统PPT文件，是一个index.html。浏览器打开，左右键翻页，可以演示、发送、截图，也能继续让AI修改。

它内置两套视觉系统。

**Style A：电子杂志 × 电子墨水**。适合观点表达、个人分享、叙事型演讲，有一点Monocle贴上代码的感觉。

**Style B：瑞士国际主义**。适合事实表达、产品分析、方法论、数据页、项目汇报。网格、直角、1px发丝线、高饱和锚点色、极致字号对比。

重点来了。

这两套风格不是「换一套CSS」那么简单。它是一套更严格的版式系统：22个具名版式、4套锚点色、16列grid、强校验脚本。

**普通AI PPT翻车，不是因为AI不会生成页面，是因为风格乱。一页像咨询公司，一页像小红书，一页像简历模板。这个Skill的思路是：给AI一套固定视觉系统，减少它自由发挥的空间。自由少一点，稳定性反而高很多。**

## 为什么HTML PPT更适合AI？

这块我要重点讲。

AI Agent（Claude/Codex/Hermes）最适合处理什么？文本、代码、文件、流程。

HTML/CSS本身就是文本。AI可以直接读，可以直接改，可以对照规则检查，也可以在浏览器里预览。

你让AI直接做普通PPT，它会卡在文件格式、版式控制、图片嵌入、预览反馈这些环节。HTML deck的好处是结构透明：

- 标题在哪
- 图片在哪
- 布局是哪种
- 样式怎么写
- 页面怎么切换
- 哪些地方可以校验

这些都能被AI读出来。

**对AI用户来说，这意味着演示稿不再只是「最后手工整理一下」的产物，而可以变成工作流的一部分。**

长文 → 提炼核心观点 → 生成7页网页演示稿

项目方案 → 拆成结构 → 生成瑞士风汇报页

产品说明 → 做成内部分享deck

方法论 → 变成一组可截图页面

比单纯输出Markdown更容易传播，也更容易给团队看。

## 这个Skill最值得学的是什么？

**「约束」两个字。**

很多人让AI做PPT，会给一句很虚的提示：帮我做得高级一点。

这句话几乎等于没说。

guizang-ppt-skill的做法不一样。它把风格、布局、图片、校验都拆成明确规则。

以瑞士风为例。它不是换一套CSS，而是一套更严格的版式系统：

- 正文页只能从S01到S22这22个具名版式里选择，不能临时发明页面结构
- 有4套锚点色（克莱因蓝、柠檬黄、柠檬绿、安全橙），只能选不能自定义
- 16列grid、直角色块、1px发丝线、无阴影、无渐变、无圆角
- 图片必须进入模板预留的data-image-slot
- 还提供校验脚本，拦住居中标题、实验版式、SVG内写字、图片脱离槽位等问题

**让AI稳定产出，不靠「审美好一点」这种模糊要求，而靠：**

- 固定风格
- 固定版式
- 固定槽位
- 固定检查清单
- 固定校验脚本

这就是高质量Skill和普通提示词的区别。

普通提示词靠模型当场发挥。

高质量Skill把可重复的东西写进结构里。

你自己做Skill也可以照这个思路来：别只写「请认真完成」，要把输入、流程、模板、禁止事项、验收标准都写进去。

## 怎么安装和最小测试？

项目给了两种安装方式。

**方式一：一行命令**

```
npx skills add https://github.com/op7418/guizang-ppt-skill --skill guizang-ppt-skill
```

**方式二：手动克隆**

```
git clone https://github.com/op7418/guizang-ppt-skill.git ~/.claude/skills/guizang-ppt-skill
```

装完以后，检查目录：

```
ls ~/.claude/skills/guizang-ppt-skill
```

你应该能看到：SKILL.md、assets/、references/、scripts/。

已经安装过的话，可以进入目录更新：

```
cd ~/.claude/skills/guizang-ppt-skillgit pull
```

如果生成的是瑞士风deck，可以用校验脚本检查：

```
node scripts/validate-swiss-deck.mjs path/to/index.html
```

触发方式也很直接，对Agent说：

```
帮我基于这篇文章做一份瑞士风PPT，控制在7页左右，需要2-3张配图。
```

**我的建议是先不要急着照搬安装。更稳的做法是先让AI研究这个Skill的结构：**

```
请研究guizang-ppt-skill的SKILL.md、assets、references和scripts结构。不要生成PPT。先告诉我：1. 这个Skill的输入是什么；2. 它如何选择风格；3. 它如何约束版式；4. 它如何做质量检查；5. 如果要迁移成你自己的Skill，哪些文件必须保留，哪些需要改写。
```

因为读者未必马上需要做PPT，但一定能从它的结构里学到：一个能稳定产出的Skill应该怎么组织。

## 适合谁，不适合谁？

**这个Skill很适合几类人：**

**第一，常做分享的人。** 线下分享、内部讲话、产品发布、demo day、私享会，都适合用HTML deck。不需要从零设计版式，先让AI产出一个能看的初稿，再人工微调。

**第二，经常整理长资料的人。** 一篇长文章、一份产品说明、一组调研笔记，直接看很累。拆成6-10页演示稿，更容易讲，也更容易传播。

**第三，想研究高质量Skill的AI用户。** 这个项目的价值不只是PPT。它把模板、布局、图片提示词、截图适配、检查清单和校验脚本放在一起，适合拿来学习Skill怎么做成「系统」。

**不适合的场景也很明显：**

大段表格数据不适合。培训课件不适合，信息密度可能不够。需要多人反复协作编辑的传统PPT流程，也不适合静态HTML。

还有一点要提醒：网页PPT很适合展示和传播，但如果客户或团队强依赖PowerPoint编辑流程，那它不一定能直接替代.pptx。
