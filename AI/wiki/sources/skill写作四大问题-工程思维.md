# Skill 写作四大问题：工程思维写 Skill

**来源：** 写Skill别急着动手，先问自己这四个问题.md
**摄入日期：** 2026-05-30
**类型：** 文章
**公众号：** 小爽爽学智能体鸭

## 摘要

作者从"有想法直接写"到理解"Skill 需要工程思维"的认知升级。Skill 本质是解决高频固定流程的操作手册，不是轻量版 Agent。Skill 不是攒得越多越牛——留下的每一个都得是经过验证的、值得维护的工程资产。工程化思路让 Skill 从一次性交付变成持续迭代的工程资产。

## 核心观点

### 需求该不该做成 Skill（第一问）
- **高频 + 流程固定** 才值得制作
- **固化的是流程偏好，不是补模型能力短板**
- 反面教材：小红书风格优化 Skill → 模型升级后 AI 自己就会，Skill 反成累赘

### 补能力 vs 固偏好（第二问）
- **补能力型**：教模型做它原本搞不定的事（如特殊格式处理），盯保鲜期，模型学会就该退役
- **固偏好型**：模型能做但要按你的标准来（如排版话术），盯忠实度
- 两种 Skill 盯着的东西不一样

### Skill 和 Agent 的区别
- **Agent**：决策者，看环境、定计划、选动作，运行时反思循环
- **Skill**：操作手册，不观察不决策不反思，改进发生在设计阶段
- **Agent 做决策，Skill 做执行**

### Skill 怎么长出来：归纳 + 演绎
- **归纳**：从具体例子抽出通用规则
- **演绎**：用规则到具体场景检验，发现问题补规则
- 循环：归纳→演绎→再归纳→再演绎

### 怎么判断 Skill 好不好：三种对比
- **Evals（有 Skill vs 没 Skill）**：抓退化，判断是否过时
- **Comparator（新 vs 旧版本）**：A/B 盲测
- **Benchmark（模型升级后 vs 前）**：性能仪表盘追踪趋势

### Skill 开发 8 步循环
定义任务→写草稿→小规模测试→看结果→人工复核→修改→扩大测试集→继续迭代

### Skill CI/CD 流水线
改→测→审→发，用版本管理 + 自动测试集 + 报告

### 敢删：最难的一步
- 补能力型 Skill 模型学会后就是负资产
- 偏好型 Skill 标准变了还在按过时规矩拉输出
- 没有退役机制的 Skill 库早晚变垃圾堆

### 驾驭者两种脑子
- **理性脑**：精确、结构化、能验证（JSON schema、Mermaid 流程图、Evals）
- **感性脑**：模糊、创造性、要审美（风格种子、自然语言偏好）

### 四大骨架
- **流程骨架**：先干啥后干啥（时间线）
- **规范骨架**：每步按什么标准（锚点）
- **能力骨架**：谁来干（子 Skill、工具、API）
- **任务骨架**：输入输出怎么算成功（起点终点）

## 四大核心问题

1. 这个需求我每周都在做吗？流程够固定吗？
2. 这 Skill 是补能力还是固偏好？要是补能力，我准备好接受它有一天会过时吗？
3. 我的验证方案，能不能用数据替掉感觉？
4. 如果有一天它该退役了，我有勇气删掉它吗？
