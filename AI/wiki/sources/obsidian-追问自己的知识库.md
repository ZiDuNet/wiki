# Obsidian追问自己的知识库

> 来源：一个程序猿的异常 | 用 Obsidian + LLM-Wiki 打造能追问自己的知识库

## 核心观点

真正拖垮知识管理的，不是资料太少，而是资料进来之后再也醒不过来。

**定位转变：**
- 不要一上来追求"第二大脑"
- 先做一个能回答你问题的小脑袋

---

## 一、别把 Obsidian 当"高级文件夹"

### 常见症状

- 文件越来越多，命名越来越随缘
- 标签像许愿池，什么都往里扔
- 明知道自己记过，但就是找不到

**结果：** Obsidian 从"知识库"变成"资料停车场"

### 正确定位

**三个角色分工：**
- Obsidian：负责长期存放
- AI：负责第一轮整理和追问
- 人：负责判断

**关键：** 把它们接成一个闭环

---

## 二、最小闭环：先让20篇笔记活起来

### 从小主题开始

推荐起点：
- 10-20篇 AI 工具文章
- 一个项目的会议纪要和复盘
- 一组读书笔记
- 一个准备长期写作的专题素材

### 笔记必备四要素

| 要素 | 说明 |
|------|------|
| 清楚标题 | 不要叫"未命名12" |
| 完整上下文 | 不要只贴半句话 |
| 原始链接/出处 | 方便回头校验 |
| 自己的判断 | 这条资料为什么值得留下 |

**原则：** 笔记质量越像食材，AI整理出来的东西越像菜

---

## 三、LLM-Wiki 的价值

### 不是"帮我总结"

LLM-Wiki 更像"临时研究助理"：
- 从一组笔记抽概念、建页面、补链接、生成索引
- 允许围绕材料继续追问

### 典型流程

```
选定小主题文件夹 → Ingest from Folder → 生成 wiki/index.md 和概念页 → Query Wiki 追问 → 回到原文校验 → 补充缺口
```

### 三个核心价值

1. 把散落的概念拉到台面上
2. 把相关笔记连起来
3. 让我能围绕自己的材料提问

---

## 四、好的追问问题

### 错误问题

> "个人知识库有什么用？"

这跟你的 Obsidian 没关系，任何通用大模型都能回答

### 正确问题（绑定材料）

> 我最近保存的 AI 工具文章里，哪些适合变成可执行教程？
> 我的项目复盘里，反复出现的风险点是什么？
> 过去一个月的公众号素材，能不能拆出三个选题方向？
> 哪些笔记只有观点，没有案例，发出去会显得空？

### 判断标准

好的 AI 知识库能让你少做三件事：
1. 少翻旧文件
2. 少重复搜索
3. 少从零开始组织观点

---

## 五、入口自动化流程

### 结构设计

```
微信公众号/
  原文/
    公众号作者/
      日期 标题/
        日期 标题.md
        images/
  改写/
    日期 改写标题/
      日期 改写标题.md
      images/
```

### 分工原则

- 原文区 = "证据"
- 改写区 = "产出"

**知识库起飞关键：** 入口、结构、追问、校验这四步终于连上了

---

## 六、必须校验

### AI整理三类错误

| 错误类型 | 示例 |
|----------|------|
| 误读否定 | 原文说"不适合小团队"，总结成"适合团队协作" |
| 乱拉关系 | 两个词长得像，硬说有关 |
| 漂亮废话 | 原文只有一句感受，扩成一段宏大判断 |

### 校验检查项

```
重要结论能不能回原文？
概念链接是不是真的相关？
有没有把不同主题混在一起？
有没有缺少来源的判断？
有没有不该发给云端模型的私人内容？
```

**关键：** 个人知识库的价值不是"AI说了什么"，而是能否帮助更快回到证据

---

## 七、7步开始

| 步骤 | 动作 |
|------|------|
| 1 | Obsidian建小主题文件夹 |
| 2 | 放入10-20篇质量不错的笔记 |
| 3 | 每篇补清楚标题和自己的判断 |
| 4 | 安装配置LLM-Wiki类插件 |
| 5 | 只处理这个小文件夹 |
| 6 | 问3个和材料强相关的问题 |
| 7 | 回到原文校验，再补缺口 |

---

## 最后

真正靠谱的个人知识库，往往很笨：
- 本地 Markdown
- 清楚目录
- 稳定入口
- 少量主题
- 反复校验

但它真的有用——当你写文章、做方案、复盘项目时，它会提醒你：

**你以前想过什么，保存过什么，哪些材料能用，哪些地方还缺证据。**
