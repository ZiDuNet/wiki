# Markdown 负责记忆，HTML 负责展示：AI 时代的新内容分工

## Summary

基于 Thariq Shihipar (Anthropic Claude Code 团队) 的观点，AI 工作流中 Markdown 和 HTML 应有明确分工：Markdown 负责底层逻辑与记忆的纯净存储（像仓库），HTML 负责对外的高密度交互与展示（像展厅）。当 AI 能生成复杂计划、报告、原型时，Markdown 的轻便优势不再占上风，HTML 反而能把信息组织得更清楚、更容易被审查。

## Key Claims

1. **Markdown = AI 时代的记忆格式** — 底层存储最怕：看起来很炫但不好改、格式复杂但不好追踪、页面好看但 AI 下次读取噪声太多
2. **HTML = 把 AI 的思考变成人能审查的界面** — 不是让内容变漂亮，而是让复杂内容重新可审查
3. **真正好用的分工**：Markdown 管逻辑（保存判断），HTML 管表达（呈现判断）
4. **HTML 接管展示任务，Markdown 继续承担底层记忆任务**

## Limitations / Bias

- HTML 更耗 Token、生成更慢
- 复杂页面在版本控制里差异会很乱
- 不需要把每份小笔记都做成 HTML

## Three-Practice Workflow

1. **先用 Markdown 保存逻辑** — "请先把这些资料整理成 Markdown 版底稿"
2. **再让 AI 生成 HTML** — "基于这份 Markdown，生成一个单页 HTML 展示稿"
3. **审查后更新 Markdown** — "请把新的判断更新回 Markdown 底稿"
