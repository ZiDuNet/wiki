# 知识库系列（一）：用 Obsidian 把散落的材料收成一棵树

> 来源: 武见说 | 时间: 2026-05-29

## 核心命题

用 Obsidian 把团队散落各处的资料收集、组织、利用起来，再让团队里所有人都能浏览、贡献、协作。

---

## 仓库：Docs As Code 的表达

**仓库（vault）** = "Docs As Code" 理念的表现——把文档像代码一样，集中存放在某个文件夹中。

本质是磁盘上的一个文件夹，所有 markdown 文件、图片、附件都属于这个仓库：
- 不依赖任何云服务
- 迁移和备份极其方便
- 能被 Git 管理（团队协作地基）

---

## 工作区四区域

1. **仓库切换及设置（左下角）**——切换不同文档仓库，个性化设置：主题、字体、插件配置
2. **插件边栏（左侧细长条）**——Obsidian 核心插件和第三方插件快捷入口
3. **侧边栏（左右两侧）**——左侧文件树增删改查、全仓库搜索；右侧目录大纲、反向链接等
4. **阅读区（中间）**——查看和编辑文档，支持分栏阅读

---

## 五个基本用法

### 1. 新增文件/文件夹
左侧边栏右键新建，默认 markdown 格式。

### 2. 引用文件（[[wikilink]]）
`[[B]]` 建立从 A 到 B 的关联。孤岛文件越少越好——谁都链不到、自己也不链别人的文档写了等于没写。

### 3. 反向链接
A 引用了 B → 站在 B 的角度，A 就是它的反向链接。Obsidian 自动维护，不用手动登记。
- 正向引用：「我提到了谁」
- 反向链接：「谁提到了我」
- 两个方向都通，知识才算真正「连」上。

### 4. 标签（#tag）
横向归类。标签和文件夹是两套维度：
- 文件夹管「东西放在哪」
- 标签管「东西属于哪一类」
- 一个文件只能待在一个文件夹，却能同时挂好几个标签。

### 5. 附件
所有非 md 文件（图片、PDF、Word、Excel、PPT、txt 等）都以附件形式存在。直接拖入编辑器，Obsidian 自动收进附件文件夹并生成引用。

---

## 高频使用场景

### 会议记录
新建「01-会议记录」文件夹，以 `日期-会议主题` 格式命名。开会前建好，会议中实时记。

### 写材料
写文字 + 拖入附件。支持源文件模式和预览模式，左右分栏对照。

### 索引材料
新建导航文件，只用 `[[]]` 引用其他文件。索引文件本身不放具体内容，纯粹用作入口和聚合。「轻索引、重内容」模式对抗孤岛文件。

## 进阶增强

1. **调整主题**——推荐 "Blue Topaz"，布局紧凑，信息密度高
2. **Dataview 插件**——把仓库当数据库用，类 SQL 语法查询文件
3. **Excalidraw 插件**——内嵌画图工具，画架构图、流程图、白板涂鸦

---

## 为什么是 Obsidian

| 工具类型 | 问题 |
|---|---|
| 编辑器 + 文件夹（Sublime Text） | 没有文件关联、渲染、反向链接 |
| 云服务工具（Notion/语雀） | 内容存服务器私有格式，迁移麻烦，Git 版本管理难 |
| 卡片笔记（flomo） | 擅长快速输入，但组织成系统是短板 |
| Zettelkasten 工具 | 过于强调形式，负担重或太小众 |

**选 Obsidian 理由**：
1. 数据是你自己的——本地纯文本 markdown 文件
2. 能被 Git 管理——版本控制天然支持
3. 关联能力强——双向链接、反向链接、关系图谱
4. 本地优先、离线可用、插件可扩展
