# 企业级组织记忆

**类型:** 概念

## 定义

用 LLM Wiki + Context + Memory 构建的 AI 时代企业级知识体系，解决组织遗忘问题。知识不是"存起来备查"，而是"编译进去活起来"。

## 核心问题

人类的记忆会遗忘，组织会遗忘，甚至整个行业都会遗忘。Vannevar Bush 在 1945 年就设想了 Memex——一种个人策划的知识库，文档间有关联轨迹。他无法解决的是谁来维护这些链接。**80 年后，LLM 解决了这个问题。**

## 从个人到团队的演进

| 层级 | 特点 | 工具 |
|-----|------|------|
| 个人 | 快速迭代，自主决策 | Obsidian + Claude Code |
| 小团队 | 共享源文件，分工维护 | Obsidian Git 同步 + MCP |
| 部门 | 统一 Schema，权限控制 | Notion + Claude API |
| 企业 | 多语言支持，大规模检索 | 定制 RAG + Wiki 混合 |

## 四层 Memory 架构

| 记忆类型 | 内容 | 实现位置 |
|---------|------|---------|
| Working Memory | 当前会话上下文 | LLM 自动维护 |
| Episodic Memory | 过去的会话历史 | Wiki log.md |
| Semantic Memory | 结构化知识、概念、关系 | Wiki 概念页面 |
| Procedural Memory | 操作流程、Schema 规范 | CLAUDE.md |

## 与传统知识管理的区别

| 传统方式 | LLM Wiki 方式 |
|---------|-------------|
| 知识存起来备查 | 知识编译进去活起来 |
| 每次查询重新发现 | 知识累积增长 |
| 人工维护链接 | LLM 自动维护 |
| 知识是消耗品 | 知识是可复合资产 |

## 关键洞察

> "维护知识库最繁琐的不是阅读或思考，而是 bookkeeping。LLM 不会厌倦、不会忘记更新交叉引用，一次能处理 15 个文件。"

## 三项核心操作

1. **Ingest**：知识的编译——将源文件"编译"成 Wiki 页面
2. **Query**：知识的查询——综合分析与引用，沉淀有价值回答
3. **Lint**：知识的维护——定期健康检查，确保 Wiki 不会"腐烂"

## 企业落地要点

1. 分层索引：全局 index.md → 子目录 index.md → 具体页面
2. 语义搜索：BM25 + 向量混合搜索 + LLM 重排序
3. 选择性上下文：根据问题选择相关页面
4. Git 协作：所有成员克隆同一仓库，分支管理不同主题
5. Schema 分发：CLAUDE.md 是模板，新成员自动获得工作流规范
6. CI/CD 自动化：GitHub Actions 自动运行 Lint
