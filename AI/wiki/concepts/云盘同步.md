# 云盘同步

**类型:** 概念
**提及文章数:** 1

## 简介

云盘同步是指使用 iCloud、OneDrive、坚果云等云盘服务来同步 Obsidian 文件夹的方案。这是很多用户最早接触的同步方案，因为足够直观：创建云盘同步文件夹 → 放入 Obsidian 仓库 → 所有设备同步该文件夹。

## 核心思路

> 用云盘来同步 Obsidian 文件夹。

因为 Obsidian 的仓库本来就是普通文件，理论上任何支持文件同步的云盘都可以拿来同步 Obsidian。

## 主要云盘方案

### iCloud：苹果生态最佳

| 特性 | 说明 |
|---|---|
| 适用人群 | Mac、iPhone、iPad 用户 |
| 优势 | 原生系统集成、不需要第三方插件、多设备切换顺滑 |
| 问题 | \"优化存储\"机制可能自动转移文件到云端 |
| 建议 | 关闭\"优化存储\"，确保仓库文件始终保存在本地 |

### 坚果云：国内用户常见选择

| 特性 | 说明 |
|---|---|
| 适用人群 | 国内用户 |
| 优势 | 国内速度快、免费可用、配置简单、对 Markdown 仓库友好 |
| 限制 | 上传流量约 1GB/月、下载流量约 3GB/月 |
| 注意 | 纯文本笔记够用，图片/PDF/AI素材可能很快触顶 |

### OneDrive：Windows 用户天然选择

| 特性 | 说明 |
|---|---|
| 适用人群 | Windows、Office 用户 |
| 优势 | 系统自带、Office 用户默认登录 |
| 问题 | 文件锁定，可能误判文件正在使用导致同步失败 |
| 建议 | 关闭\"Files On-Demand（文件随选）\" |

## 云盘方案的共同弱点

### [[同步冲突处理]] 能力一般

当手机和电脑同时修改同一个文件时：
- 云盘通常会直接生成一个冲突副本
- 需要用户手动合并内容

### 铁律

> **不要同时在两台设备编辑同一个文件。**

## 常见坑

1. **第一次同步前先备份仓库** — 避免同步异常导致数据丢失
2. **仓库里不要放大量视频文件** — 会严重拖慢同步速度
3. **移动端注意云盘 App 后台存活状态** — 被系统杀掉后同步会中断
4. **频繁切换设备时给云盘留同步时间** — 再开始编辑

## 与其他方案对比

| 对比项 | 云盘方案 | Obsidian Sync | Git | Remotely Save + WebDAV |
|---|---|---|---|---|
| 价格 | 免费/低 | $48/年 | 免费 | 插件免费 |
| 冲突处理 | 弱 | 强 | 强 | 中 |
| 技术门槛 | 低 | 低 | 高 | 中 |
| 配置复杂度 | 简单 | 简单 | 复杂 | 中等 |

## 适用人群

- 轻量用户（纯文本笔记为主）
- 单生态用户（苹果全家桶 → iCloud，Windows → OneDrive）
- 不想折腾技术配置
- 对冲突处理要求不高（能做到不同时编辑同一文件）

## 云盘方案 vs WebDAV

| 对比项 | 云盘方案 | WebDAV 方案 |
|---|---|---|
| 协议 | 各云盘私有协议 | WebDAV 标准协议 |
| 冲突处理 | 弱 | 中等（配合 Remotely Save） |
| 数据自主 | 数据在云盘厂商 | 数据可自管（NAS） |
| 国内速度 | iCloud 慢、坚果云快 | 坚果云/NAS 快 |
