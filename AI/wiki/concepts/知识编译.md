# 知识编译

**类型:** 概念

## 定义

将 LLM 用于「编译知识」而非「写代码」。原始素材（raw/）通过 LLM 处理，自动生成结构化的 Wiki（摘要、概念文章、索引、反向链接）。

## Karpathy 洞察

> "A large fraction of my recent token throughput is going less into manipulating code, and more into manipulating knowledge."

Token 去向变了——从写代码转向编译知识。他不手动编辑 wiki，这是 LLM 的领域。

## LLM 编译六件事

1. 读取 raw/ 目录，扫描原始数据
2. 生成摘要（每篇文章核心观点）
3. 分类整理（按概念归类）
4. 生成文章（每个概念写专题）
5. 创建索引（自动维护 index.md）
6. 添加反向链接（文章间关联）

## 关键发现

~40 万词规模下，**不需要 RAG**。LLM 自动维护的索引表现良好。原因：LLM 能「理解」知识结构，不是机械检索关键词。

## 增长机制

输出结果归档回 wiki，每次查询都「增加」知识库。知识是累积的，不是消耗的。

## 企业级扩展

三层架构：`Raw Sources → Wiki → Schema`

| 层级 | 说明 | 特点 |
|-----|------|------|
| Raw Sources 源文件层 | PDF、论文、文章、播客笔记 | 不可变，LLM 只读取不修改 |
| The Wiki Wiki层 | 摘要页、概念页、实体页、对比分析 | LLM 维护，你读它，LLM 写它 |
| The Schema 规范层 | CLAUDE.md / AGENTS.md | 定义 Wiki 结构、操作流程、格式约定 |

三项核心操作：
1. **Ingest**：知识的编译——将源文件"编译"成 Wiki 页面
2. **Query**：知识的查询——综合分析与引用，沉淀有价值回答
3. **Lint**：知识的维护——定期健康检查

## 企业级 Memory 处理

| 记忆类型 | 内容 | 实现位置 |
|---------|------|---------|
| Working Memory | 当前会话上下文 | LLM 自动维护 |
| Episodic Memory | 过去的会话历史 | Wiki log.md |
| Semantic Memory | 结构化知识、概念、关系 | Wiki 概念页面 |
| Procedural Memory | 操作流程、Schema 规范 | CLAUDE.md |
