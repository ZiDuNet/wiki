# LLM-Wiki

**提出者:** [[Karpathy]]
**来源文章:** [[通过飞书妙搭构建LLMWiki应用的实战指南]]

## 定义

Karpathy 在 GitHub Gist 分享的知识管理模式，让 LLM 维护结构化 Wiki 而非每次检索。核心思想：知识真正被"编译"一遍。

## 三层架构

```
Raw Sources（源文档） → Wiki（LLM 维护的结构化页面） → Schema（维护规则）
```

## 核心特点

- **Wiki 是活的** — 不是静态存档，而是持续更新
- **Wiki 是累积的** — 新文档增量写入，不是每次从零
- **Wiki 是自我更新的** — 提取关键信息 → 更新交叉引用 → 标注矛盾点

## 与传统 RAG 的对比

| 传统 RAG | LLM Wiki |
|----------|----------|
| 每次回答从零理解 | 回答已被整理的知识 |
| 没有记忆积累 | Wiki 持续累积 |
| 文档间关系靠临时拼接 | 文档间关系已整理 |
| 问综合问题需多次检索 | 一次回答有上下文 |

## 关键机制

- **log.md** — 时间线日志，记录每次"消化新文档"和"提问"事件
- **交叉引用** — 产品功能页提到"报销"，链接到报销流程页
- **矛盾标注** — 发现信息冲突时标注，同时引用两个来源
