# 同步冲突处理

**类型:** 概念
**提及文章数:** 1

## 简介

同步冲突处理是指当多台设备同时修改同一文件时，同步系统如何处理这种情况的能力。这是 Obsidian 多端同步方案对比的核心维度之一。

## 问题背景

Obsidian 采用 [[本地优先]] 设计，数据首先存在本地。当在不同设备上编辑同一笔记时：
- 公司电脑写了一半的内容
- 手机上修改了同一篇笔记
- 两台设备同时编辑了同一个文件

这时就可能产生同步冲突。

## 不同方案的冲突处理能力

|| 方案 | 冲突处理能力 | 说明 |
|---|---|---|---|
| [[Obsidian-Sync]] | 强 | 对冲突做了深度适配，丢数据概率低 |
| [[云盘同步]] | 弱 | 生成冲突副本，需手动合并 |
| Git + GitHub | 强 | 完整版本控制，支持 Merge |
| [[Remotely-Save]] + [[WebDAV]] | 中 | 有一定冲突处理能力，但不如官方 Sync |

## 云盘方案的冲突处理弱点

当在手机和电脑上同时修改同一个文件时：
- 云盘通常直接生成一个\"冲突副本\"（conflict copy）
- 需要用户手动合并内容
- 可能导致数据丢失

### 云盘方案铁律

> **不要同时在两台设备编辑同一个文件。**

### 使用云盘方案的建议

1. 频繁切换设备时，给云盘留一点同步时间再开始编辑
2. 移动端注意云盘 App 的后台存活状态（被系统杀掉后同步会中断）
3. 第一次同步前先备份仓库
4. 仓库里不要放大量视频文件（会拖慢同步）

## Obsidian Sync 的优势

官方 Obsidian Sync 对冲突问题做了更深度的适配：
- 不是简单的\"谁最后上传覆盖谁\"
- 系统知道应该保留哪个版本
- 丢数据的概率低很多

## Git 方案的冲突处理

Git 作为完整版本管理系统：
- 知道哪天改了什么、删除了什么、增加了什么
- 能精确对比不同版本之间的差异
- 出现冲突时可执行 Merge 操作
- 但需要理解 Commit、Push、Pull、Merge、Branch、Conflict 等概念

## Remotely Save + WebDAV 的冲突处理

介于云盘和官方 Sync 之间：
- 有一定的冲突处理能力
- 不如官方 Sync 的深度适配
- 相比云盘方案有所改善

## 冲突处理等级总结

| 等级 | 方案 | 特点 |
|---|---|
| 强 | Obsidian Sync、Git | 深度适配/版本控制，低丢数据风险 |
| 中 | Remotely Save + WebDAV | 有一定处理能力 |
| 弱 | iCloud/OneDrive/坚果云 | 生成冲突副本，需手动合并 |
