# Skill工程化

**类型:** 方法论

## 简介

Skill 工程化是将软件工程的测试、迭代、CI/CD 方法引入 Skill 创作和维护的思路。核心观点：Skill 不是攒得越多越牛——留下来的每一个都得是经过验证的、值得维护的工程资产。Skill 本质是解决高频固定流程的操作手册，不是轻量版 Agent。

## 核心框架

### 四大问题（写 Skill 前必问）
1. 这个需求每周都在做吗？流程够固定吗？
2. Skill 是补能力还是固偏好？
3. 验证方案能不能用数据替掉感觉？
4. 有勇气在 Skill 该退役时删掉它吗？

### Skill 两种类型
- **补能力型**：教模型做它原本搞不定的事，盯保鲜期，模型学会就该退役
- **固偏好型**：模型能做但要按你的标准来，盯忠实度

### 三大质量验证
- **Evals**（有 Skill vs 没 Skill）：抓退化，判断是否过时
- **Comparator**（新 vs 旧版本）：A/B 盲测
- **Benchmark**（模型升级后 vs 前）：性能仪表盘追踪趋势

### 四大骨架
- 流程骨架：先干啥后干啥（时间线）
- 规范骨架：每步按什么标准（锚点）
- 能力骨架：谁来干（子 Skill/工具/API）
- 任务骨架：输入输出怎么算成功（起点终点）

### 开发 8 步循环
定义任务→写草稿→小规模测试→看结果→人工复核→修改→扩大测试集→继续迭代
